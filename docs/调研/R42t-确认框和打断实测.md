## Claude Code：未测成的原因与停点

实例 `98240cc5c365`，屏幕显示 Opus 5.5 with high effort、`auto mode on`。虽然启动时没有传免确认参数，实际会话显示自动模式；没有读取或修改用户配置，自动模式的来源未查证。

1. **Bash 权限框、Enter 仅批准一次**：第一轮要求 Bash ls，自动执行并回复已完成，没有出现权限框。因此 blocked、框中 last_output 稳定性、框上 Esc、拒绝后 send、Enter 的批准范围都没有有效样本。
2. **干活中 Esc**：第二轮要求前台 sleep 30，被 Bash 工具直接拒绝，没有实际跑起来，没有发送 Esc。最后为 idle、interrupted 为 false、last_tool 为 null。不能当成成功打断。
3. **AskUserQuestion 两题（含多选）**：未开始；因此是否 blocked、一次能看到几题、last_output、Esc 后状态、send 均未知。
4. **--permission-mode plan 的计划批准**：未开始；对应状态、屏幕、等待刷新、Esc 与 send 均未知。
5. **提问框钩子中的完整 tool_input**：没有提问框样本，未读取测试 agent 的事件文件，无法给出本轮收到哪些提问事件或哪个钩子携带完整题目的动态证据。下面只列静态代码事实。

### 静态代码事实（不冒充动态实测）

- `crates/corral/src/agents/claude.rs` 的 hook_args 通过 --settings 注册 SessionStart、UserPromptSubmit、PreToolUse、PostToolUse、PermissionRequest、Notification、Stop、StopFailure、SessionEnd；工具相关三个钩子 matcher 为 *。
- `crates/corral/src/pen.rs` 设置事件路径为该 agent 状态目录的 events；state.rs 按 CORRAL_HOME（默认 ~/.corral）和 agent 名字拼路径。
- 当前仓库 hooks.rs::run 读钩子 stdin JSON，但落盘字段白名单只包含 session_id、transcript_path、cwd、source、tool_name、prompt、last_assistant_message、notification_type，以及派生的 has_transcript、background_running 和事件元数据；**没有 tool_input**，不保存原始 stdin。
- 因而“仓库这版采集逻辑不持久化完整题目”有代码依据；“本轮 AskUserQuestion 到底发了哪些钩子、原始输入是否带题目”仍未知。HANDOFF 说明共用 helper 是 aef2b4a，本轮没有换 helper，也没有把当前源码直接当作已安装 helper 的动态证据。
- events.rs 中 PermissionRequest 设置 blocked；Notification 仅 permission_prompt 设置 blocked；PreToolUse/PostToolUse 设置 working。这不能替代实际确认 AskUserQuestion、ExitPlanMode 发哪些事件。

### 为什么停止本轮

工具明确报错（仅去掉换行前的行尾空格）：

~~~text
Error: Blocked: standalone sleep 30. To wait for a condition, use Monitor with an until-loop (e.g. `until <check>; do sleep 2;
done`). To wait for a command you started, use run_in_background: true. Do not chain shorter sleeps to work around this block.
~~~

任务要求全部前台运行，并规定遇到要拿主意的事停止、等主控回复。没有尝试后台、拆短 sleep、改用其他命令绕过拦截，也没有自行更换权限模式重开 Claude Code。测试 agent 已 stop。

主控可选：

- **建议**：把本轮 Claude Code 干活打断记为未测成，先授权继续其余三个框；权限测试会话显式使用 --permission-mode default，保持逐次确认，不改全局配置。如果仍不弹权限框，再报告现象。
- 若必须覆盖 sleep 工具运行中的打断，另行决定是否允许这一条 sleep 在后台运行；这需要放宽前台要求，而且只能验证该执行方式的行为。
- 若保持前台且必须验证干活打断，可另定测试命令或测试“模型生成期间的 Esc”；需要主控明确范围，不能替换成同一个结论。
