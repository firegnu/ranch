# R42：在手机上回答确认框、打断这一轮、`@pony ?` 多给信息（设计稿）

2026-10-22，ranch/dev-r42。只出设计：不写代码、不改 DESIGN、不改 Slack 应用、不部署、不碰在跑的 agent。依据：`docs/任务/R42-手机上回答确认框和打断-设计.md`、R39 第三档第 5–7 条、DESIGN §7（各家适配器、读屏、打断）和 §10、R38a 3.3–3.10、CONTRACT（R22 打断、`pony status`）。corral 和 pony 的行为都对照代码核对过，见文末「核对过的」；Slack、Claude Code 的文档出处在文末，都是 10-22 查的。

## 结论

- **能做，建议分两步。**
  - **第一步**不改 Slack 应用，也不远程按「允许」：
    - `@pony ?` 多给信息；
    - 在线程里回一句「停」，pony 就替你按一次 Esc，打断这一轮。会话留着；agent 停在框上时，这一下等于拒绝这个框；
    - Needs you 提醒带上屏幕末尾几行，手机上看得到它在问什么。
  - 有了这三样，提问框可以从手机答：在线程里写回答，再回一句「停」。框被关掉，agent 空下来，排着的回答就送过去。
  - 但有个前提：拒绝之后，corral 要认得出 agent 已经空下来。**Claude Code 停在框上被 Esc 拒绝，现在多半认不出**：R24 只在干活、空闲时读对话记录，corral 订的钩子里也多半没有一个会来，所以它会一直报 `blocked`，排着的回答送不进去。这一条要实测；属实的话要修 corral（第 6 节 (d)），交用户定（「要用户定的」第 3 条）。修好之前，Claude Code 上的「停」只能打断干活中的一轮，或单纯关掉框。
  - **第二步**开 Slack 交互，给按钮：
    - 「打断」「拒绝」两种按钮，哪家能用跟第一步的「停」一样（见 1.4）；
    - 「允许这一次」只给 Claude Code 的权限框和计划批准。点之前核对六样，点之后看反应；「永远允许」一类的选项一律不给。
- **corral 现有命令够做第一步**，除了上面 Claude Code 那一处。第二步的按钮也能做，但框里写了什么只能从 `corral read` 的尾部看，而 corral 自己的说明写着 `read`「只作排查，不要靠它做决定」。
  - 不改 corral 的办法：pony 这边多重核对，每家的识别规则写在 pony 里。
  - 更稳的办法要改 corral：钩子记下工具参数、按键带上实例号。这碰用户底线，交用户定（「要用户定的」第 3 条）。
- 很多事实只能用真实 agent 实测才知道：Claude Code 的提问框会不会报 `blocked`、`read` 尾部好不好读、`keys esc` 能不能代替人按 Esc。实测要开测试 agent、花额度，清单见「要实测的」。

## 1. 哪些框能从手机答

### 1.1 现在 corral 怎么报「在等你」

| 家 | 什么时候变成 `blocked` | `last_tool` | `state_started` | 派活时带的免确认参数 |
| --- | --- | --- | --- | --- |
| Claude Code | 钩子 `PermissionRequest`，或通知 `permission_prompt` | 有，工具名（Bash、Edit…） | 有 | `--dangerously-skip-permissions` |
| Codex | 钩子 `PermissionRequest` | 钩子带工具名时有 | 有 | `--yolo` |
| pi | 扩展弹的对话框（`ui_prompt_start`） | 不对应这个框，是之前用过的工具 | 有 | 不带参数 |
| omp | 工具等批准（`tool_approval_requested`），或 `ask` 工具开始 | 不对应这个框，是之前用过的工具 | 有 | `--approval-mode yolo` |
| amp | 终端标题以 `◆ Input needed` 开头 | 最后一次工具结果 | **空** | 无 |
| agy | 读屏：最下面 4 行非空的里同时有 `↑/↓ Navigate`、`tab Amend` | 最后一次工具 | **空** | `--dangerously-skip-permissions` |

要紧的几件事（都对照代码核对过）：

- **状态里没有框的内容。** 钩子只记 `tool_name`，不记 `tool_input`（`hooks.rs` 记的字段表）。所以 `status` 里没有命令原文、题目和选项。Claude Code 的权限钩子输入本来带 `tool_input`（官方文档），是 corral 没记。
- **amp、agy 的 `state_started` 是空的。** 它们的 `blocked` 是命令行按标题、读屏现算的，钩子那边的状态不是 `blocked`；`cli.rs` 只在两边状态一致时才给 `state_started`。所以 pony 分不清前后两个框。
- **Claude Code 批准以后，到工具跑完之前一直报 `blocked`。** 它在「批准」这一刻没有钩子，`PostToolUse` 要等工具跑完才来（`tests/protocol.rs` 的状态表：`PermissionRequest` 之后一直 `blocked`，到 `PostToolUse` 才变）。所以「还是 `blocked`」不说明框还在。
- **权限框主要出在用户自己开、没带免确认参数的会话里。** 派活开出去的 agent 都带免确认参数（`dispatch.toml`），不弹权限框。提问框不受这类参数影响：Claude Code 的 AskUserQuestion、omp 的 `ask`。
- **Claude Code 的提问框（AskUserQuestion）和计划批准（ExitPlanMode）会不会报 `blocked`，没核实。** corral 只把 `PermissionRequest` 和 `permission_prompt` 当 `blocked`；官方文档没写这两个工具会不会触发权限钩子。要实测（「要实测的」第 1 条）。如果不报，现在这两种框连 Needs you 都不发。

### 1.2 各家的框长什么样

仓库里只有 agy 一份真实画面（R8 实测，写在 `agents/agy.rs` 的测试里）：

```
Requesting permission for:
   ls -la
Run this command?
> 1. Yes, run command
  2. Yes, and always allow in this conversation for commands that start with 'ls'
  3. Yes, and always allow for commands that start with 'ls' (Persist to settings.json)
  4. No, cancel
  ↑/↓ Navigate · tab Amend · ctrl+g edit/expand command
```

R8 里 `keys enter` 选了第 1 项（只批准这一次）。另外：

- amp：只知道标题是 `◆ Input needed: <thread 标题>`（R6），框本身没有样本。
- Claude Code、Codex、pi、omp：仓库里没有框的屏幕样本。
- Claude Code 提问框的数据格式在官方文档里有：每道题有题目、短标题、2–4 个选项，可以多选，一次可以问几道。

### 1.3 pony 怎么知道停在哪种框上、有哪些选项

- **哪种框**：用 `status` 的 `kind`（公开字段，pony 现在没读）加 `last_tool` 推断：
  - Claude Code：`AskUserQuestion` 是提问框，`ExitPlanMode` 是计划批准，别的是权限框。前两个先要实测会不会报 `blocked`。
  - Codex、amp、agy：权限框。
  - pi：扩展对话框。
  - omp：分不出是权限框还是 `ask`。
- **有哪些选项**：公开命令里只有 `corral read`。它的行为：
  - 取最近若干字节的输出：默认 16000 字节，输出环一共留 512 KB；
  - 去掉控制序列，`\r` 换成换行；
  - 成功时直接打印文字，不是 JSON，pony 要单独接。
- **`read` 不是当前画面。** 界面程序每重画一次，就在输出流里留下一份。corral 的说明写着：判断「现在屏幕上是什么」只看尾部，并且只作排查，不要靠它做决定（`AGENT_USAGE.md`）。
- 第一步只把尾部给人看，不用认框。第二步要认出框和选项，得按家写识别规则：从尾部最后一次出现的框头取到末尾。这是第一次让 pony 按家写东西，R39 记过「pony 不挑家」；放 pony 里还是改 corral，见第 6 节。

### 1.4 第一版支持哪些

| 家 | 提醒里看得到在问什么（第一步） | 「停」：打断，或在框上时拒绝（第一步） | 「允许」按钮（第二步） |
| --- | --- | --- | --- |
| Claude Code | 屏幕末尾 | 打断干活中的一轮：支持。在框上拒绝：能按，但拒绝后 corral 多半一直报 `blocked`（3.2），排着的话送不进去 | 权限框「允许这一次」、计划批准「批准，之后的修改仍逐个问」 |
| Codex | 屏幕末尾 | 打断干活中的一轮：支持。在框上拒绝：要实测 | 不给：派活都带 `--yolo`，权限框少见 |
| pi | 屏幕末尾 | 支持 | 不给：扩展对话框各式各样 |
| omp | 屏幕末尾 | 打断支持；在 `ask` 框上按 Esc 是什么效果要实测 | 不给 |
| amp | 屏幕末尾 | 要连按两次 Esc；`keys` 连发两个能不能代替人按，要实测，过了才支持 | 不给：`state_started` 是空的 |
| agy | 屏幕末尾 | 不支持：打断后 corral 认不出，状态一直是 `working`（R26） | 不给：同 amp |

- 「支持」都以实测通过为前提：R22 实测各家打断都是真人按的 Esc，`corral keys esc` 能不能代替人按还没测过。
- 不支持的情况，Slack 里这样说：
  - 提醒里：`这家的框还不能在 Slack 里答，请回电脑处理`；
  - 回「停」时：`agy 被打断后 corral 认不出，没按；请回电脑`。

### 1.5 先只带题目和选项、不给按钮，能不能作为第一步

能，建议这样做。

- **好处**：
  - 不会按错：一个键都不替用户按「允许」。
  - Slack 应用不用改，凭证、清单都不动。
  - 手机上就看得到它在问什么，好决定要不要回电脑。
  - 配上「停」，提问框已经能从手机答（见下面的提醒样子）；Claude Code 要等第 6 节 (d)。
  - 用一阵就攒下各家框的真实样子，第二步要不要做、识别规则怎么写，都靠这些样本定。
- **代价**：
  - 允许类的框还得回电脑点。
  - `read` 的尾部可能很乱：界面程序重画会留下重复或残缺的几行，要实测。
  - 屏幕上可能有回复里没有的东西，比如正要改的文件内容、命令里的 token；这些会发进 Slack（只发进这个仓库的私有频道）。要不要遮盖，见「要用户定的」第 5 条。

第一步的提醒样子（屏幕末尾用 agy 的真实画面示意）：

```
⚠ ranch/dev-x 在等你（权限框，等了 1 分钟）
屏幕末尾：
~~~
Requesting permission for:
   ls -la
Run this command?
> 1. Yes, run command
  …
  4. No, cancel
~~~
要允许：回电脑处理。
要拒绝或换个说法：在这个线程写你的话，再回一句「停」。它会关掉这个框，然后收到你的话。
只回话、不说「停」：等电脑上处理完再送。
```

- 屏幕末尾取 `corral read --bytes 4000` 的最后 20 行，连续空行合并成一行，放在 `~~~` 代码块里。
- 只在这个 agent 所在仓库的频道发；其余照现在的提醒规则（相邻两轮都 `blocked`、同一次等待只发一次）。
- 「再回一句『停』，然后收到你的话」只对拒绝后 corral 认得出空下来的家这样写（3.2）。Claude Code 在第 6 节 (d) 修好之前写成：`再回一句「停」会关掉这个框；你的话要等你在电脑上说下一句才送`。

## 2. 怎么防误按

这一节讲第二步的按钮。第一步只按 Esc，它的检查见第 3 节。

### 2.1 发提醒时记下什么

记在 `state.json`，pony 重启后还在：

- 这条提醒：频道、消息 id、哪个 agent；
- 发提醒时的状态：`instance`、`kind`、`state_started`、`last_tool`、`last_output`、`last_human_input`；
- 屏幕尾部 T0；
- 每个按钮对应的键。按钮的 `value` 只放 pony 生成的随机号，不放别的数据。

只有同时满足下面两条才给「允许」按钮：

- 这家、这种框在第一版支持的范围里（1.4）；
- T0 认得出这个框，按钮对应的那一项（比如 `1. Yes`）在 T0 里看得全。

认不出就照第一步的样子发提醒，并写一句「认不出框的样子，没给按钮」。

### 2.2 点之前核对六样

pony 的核心是一个单线程循环，按钮点击和消息一样排队处理。

1. **是谁点的、点的是哪个**：点的人是 owner；频道绑着仓库；点的是 pony 发的这条提醒；按钮号认得、没用过。
2. **是不是同一个 agent**：同一个实例，没暂停。
3. **是不是同一次等待**：还是 `blocked`，`state_started`、`last_tool` 都和发提醒时一样。
4. **电脑上有没有人动过**：这次等待开始后没人在它窗口里打过字，也就是 `last_human_input` 不晚于 `state_started`。这条照 R37 主控的规矩，paddock 里打字也算。
5. **画面有没有动过**：发提醒以后 agent 没再输出，`last_output` 没变。
6. **重看一次屏幕**：`corral read` 的尾部和 T0 一字不差，按钮对应的那一项还在。

任何一样不对就不按，并把这条提醒的按钮去掉、写明原因：`框已经不在了`、`换了一个框`、`你刚在电脑上操作过`、`它重开过`、`暂停中`。换了新框的，照常发新提醒、带新按钮。

第 5 条有个前提：agent 等在框上时不再输出。如果某家等着的时候也一直刷新（比如计时），第 5 条永远过不了，那家的按钮就不能用；要实测。

### 2.3 点之后

- 先把按钮记成「已用」并存盘，再调一次 `corral keys`。只按一次，不重试。
- 10 秒内看反应：
  - 「允许」：`last_output` 变了，尾部不再是这个框。不能看状态离开 `blocked`，原因见 1.1。
  - 「拒绝」：离开 `blocked`。Claude Code 在第 6 节 (d) 修好之前，只能看画面变了，见 3.2。
- 改那条提醒（`chat.update`）：去掉按钮，写上 `已按：允许这一次（10:42）`。
- 10 秒没反应：在线程里说 `按了，没看到它有反应，没再按；请回电脑看看`。

### 2.4 用户已经在电脑上答过

- 点的时候：2.2 的第 3–6 条挡住。
- 不点的时候：pony 每 2 秒一轮，看到下面任一情况，就去掉旧提醒的按钮，写 `已在电脑上处理` 或 `框没了`：
  - 这次等待结束了：离开 `blocked`、`state_started` 变了、实例变了；
  - 等待中有人在窗口里打了字。
- 批准后的 Claude Code 还报 `blocked`，但人在窗口里按了键，`last_human_input` 会变，照样认得出。

### 2.5 过期、重复点、连点

- **过期**：按钮只在同一次等待里有效，等待一结束 pony 就去掉按钮。Slack 的交互消息本身不过期（文档里没有期限）。
- **pony 不在线时点**：Slack 收不到回执，手机上会报错，这一下作废；离线补收不补按钮，频道历史里没有点按钮的记录。
- **重复点**：第一下存盘后才按键；第二下看到「已用」，只在线程里说 `这个按钮已经按过了`。
- **两个按钮连点**：同一条提醒上的按钮共用一个记号。先处理的那下把整条记成已用，后一下被拒；核心按到达顺序一个个处理，不会两下同时按。
- **剩下的空隙**：从 `status`、`read` 核对完到 `keys` 送到，还有几十到几百毫秒。`corral keys` 不带实例、不看状态，这段时间里换了框也挡不住。见第 6 节。

### 2.6 危险的批准

建议：

- **一律不给**：
  - 「永远允许」「这次会话都允许」「之后自动接受修改」「跳过权限」这类会改变以后行为的选项；
  - amp、agy 的批准（`state_started` 是空的，分不清前后两个框）；
  - 看不全的：命令太长、尾部截断、认不出框。
- **给**：
  - Claude Code 权限框「允许这一次」；
  - Claude Code 计划批准「批准，之后的修改仍逐个问」。
  - 这两种按钮都带 Slack 自带的确认框：
    - 标题：`允许 ranch/main 这一次？`
    - 正文：工具名加框里命令的前 200 字；
    - 按钮：「允许」「算了」。
  - 「拒绝」「打断」不弹确认框，它们只会让 agent 停下。
- **代价**：
  - 每次允许要多点一下；
  - 命令长的仍要回电脑；
  - 识别规则是按 Claude Code 现在的样子写的，它升级改了框的样子就认不出。认不出就不给按钮，不会按错，只是又得回电脑。
- **更保守的做法**：根本不给「允许」按钮，手机上只能拒绝和打断（「要用户定的」第 2 条 A）。

## 3. 从手机打断这一轮

### 3.1 各家按什么键、按了认不认得出

| 家 | 按什么 | 打断后 corral 认不认得出 |
| --- | --- | --- |
| Claude Code | Esc | 认得出（R24，读对话记录末尾）。要求共用 helper 是新版；本机的 `~/.corral/.runtime/helper` 是 `aef2b4a`，含 R24（HANDOFF） |
| Codex | Esc | 认得出（R22，`Interrupt` 钩子） |
| pi | Esc | 认得出（R22，`agent_settled.aborted`）；R22 以前起的 pi 要重开 |
| omp | Esc | 认得出（R25）。但跑命令时按 Esc 只停命令，模型接着干，这不算打断 |
| amp | 连按两次 Esc（按一次只弹快捷键提示） | 认得出（R22） |
| agy | Esc | 认不出：没有结束钩子，状态一直是 `working`（R26） |

- 只按 Esc，不按 Ctrl-C、Ctrl-D，不 `stop`，会话就留着。Codex 连按两次 Ctrl-C 会退出，corral 停 Codex 的步骤就是这么做的（`agents/codex.rs`）。
- R22 的实测都是真人按的 Esc。`corral keys <名字> esc` 只送一个 ESC 字节，界面程序要等一下才认它是 Esc 键；能不能代替人按要实测。

### 3.2 怎么确认生效

- 按了以后，每秒查一次 `status`，最多 15 秒。
  - 变成 `idle` 且 `interrupted: true`：回 `X 停下了：这一轮被打断，会话还在，在这个线程接着说就行`。
  - 这一轮是 pony 送的话开的：现在已经会贴「这一轮被打断了，没有回复」，两句合成一句，不重复说。
  - 15 秒后还在 `working`：回 `按了 Esc，X 15 秒后还在干活，没再按`。omp 正在跑命令时就会这样；用户可以再说一次「停」。
- agent 停在框上时按 Esc，就是拒绝这个框。确认办法是看它离开 `blocked`、变成 `idle`；画面变了（`last_output` 变了）只说明框关掉了。
- **Claude Code 在框上被拒绝，corral 多半认不出。** 推断依据：
  - R24 认打断，只在状态是 `working`、`idle` 时才读对话记录（`events.rs` 的 `observe_transcript`），`blocked` 时不读；
  - R24 实测的是跑命令时按 Esc，那时状态是 `working`，没测过停在权限框上按 Esc；
  - corral 给 Claude Code 挂的钩子里，拒绝以后多半没有一个会来。官方文档只写了 `PermissionDenied` 用于自动模式的拒绝，人按 Esc 拒绝会触发什么没写。
  - 结果是一直报 `blocked`，直到下一句输入。`corral send` 在 `blocked` 时一律退回 `not_idle`（加 `--force` 也一样），排着的回答送不进去。
  - 人在电脑上按 Esc 拒绝也是这样，只是人接着打字，就被新输入盖过去了。
  - 要实测（「要实测的」第 1 条）。属实的话，pony 这边绕不过去，要修 corral（第 6 节 (d)）。
  - 修好之前，pony 对 Claude Code 的框按了 Esc 以后，只说 `框关掉了，但 corral 还报在等你；排着的话要等你在电脑上说下一句才送`。
- 别的家：Codex 在批准框上按 Esc 会不会发 `Interrupt` 钩子、pi 关扩展对话框（corral 认得出，会回到 `idle`）、omp 的 `ask`，都要实测。
- 线程里排着的话，等它离开 `blocked` 就照现有的排队规则送：相邻两轮都 `idle` 才送。所以在认得出的那几家上，「写回答，再说停」就是从手机答提问框。

### 3.3 在 Slack 里怎么触发

- **第一步：一句话。**
  - 在 agent 的线程里回「停」；
  - 在频道顶层发 `@pony 停`，停的是主控；
  - 发 `@pony 停 dev-x`，停的是那个 agent。
  - 只认整句：只有「停」或「打断」，或者后面只跟一个确实存在的 agent 名字。
  - 像 `停一下，先别提交` 这种照旧当成话送给 agent，和 `?` 的规则一样。
- **第二步：按钮。** 开了 Slack 交互以后，在这两处加「打断」按钮：
  - `@pony ?` 里，本频道仓库每个正在干活或等你的 agent 后面；
  - Needs you 提醒上，这时按钮叫「拒绝」。
- 一句话不用开交互，没有按钮的平台也能用，所以先做。

### 3.4 怎么防误触

- 只认 owner，只认整句。
- 离线补收到的「停」不执行，回 `离线期间发的「停」没执行`。补收的话可能是几小时以前发的。
- **只停说话那一刻的那一轮。** 按之前查 `status`，下面几种不按：
  - 不在干活、也不在等你：空闲、暂停中、启动中、读不出，各说一句；
  - 说「停」以后又开了新的一轮：`turn_started` 晚于这句话发出的时间，说 `它已经开了新的一轮，没按`。
- 30 秒内有人在它窗口里打过字就不按，说 `你刚在电脑上操作过，没按`。和 `send` 的 `human_active` 一样：`keys` 不算人在打字，corral 不替 pony 拦这个。
- 按钮版再加 Slack 确认框：`打断 ranch/main 这一轮？会话留着，只停这一轮`。
- 只按一次，不重试。

## 4. `@pony ?` 多给什么

现在的样子（`core/engine.rs` 的 `agent_summary`）：

- 干活中：`干活中，12 分钟`；
- 空闲：`空闲`，被打断的写 `空闲（上一轮被打断）`；
- 等你：`等你（对话框）`；
- 其余：`暂停中`、`启动中`、`读不出`；
- 排着话的后面加 `，排着 2 句`。

改成：

```
paddock（#paddock）
• main — 干活中 12 分钟 · 「P5-160 设置页连线」· 在用 Bash
• dev-p5-160 — 等你 3 分钟（Bash）
• dev-p5-161 — 空闲 40 分钟 · 上一句「改好了，测试全过。」
• dev-p5-162 — 空闲 · 上一轮被打断
ranch（#ranch）
• main — 空闲 2 小时
• dev-r42 — 暂停中 1 小时
```

数据都来自公开命令：

| 显示什么 | 从哪来 |
| --- | --- |
| 干活多久 | 现在减 `turn_started`（已有） |
| 等你多久 | 现在减 `state_started`。amp、agy 这一项是空的，用 pony 第一次看到 `blocked` 的时间 |
| 空闲多久 | 现在减 `reply.at`；没有回复用 `state_started` |
| 暂停多久 | 现在减 `paused_at`（公开字段，pony 现在没读） |
| 「标题」 | `status.title`，去掉首尾空白和开头的转圈符号，最多 40 字；空的、或者只是程序名的不显示。amp 会设标题（R6），agy 不设（R8），别家在仓库里没核实 |
| 在用什么 | `last_tool` |
| 上一句 | `corral reply` 的第一行非空文字，最多 60 字；`no_reply` 带 `interrupted` 的写「上一轮被打断」 |

- 只有本频道仓库里空闲的 agent 才多调一次 `reply`，每个 agent 一个进程，开销很小。

会不会泄露：

- 标题和回复第一行是 agent 写的，可能有任务名、路径、代码片段。主控的回复本来就整段发进 Slack；但派出去的 agent 的回复以前不发，这次会露出第一行。
- 建议只给**本频道的仓库**显示标题和上一句；别的仓库照旧只给状态和时长。这样一个仓库的内容不会出现在另一个仓库的频道里（「要用户定的」第 6 条）。
- 适配器已经转义 `&`、`<`、`>`，不会意外 @ 到别人。

## 5. Slack 这边要变什么

只有第二步要变，第一步不用动 Slack。

- **怎么收按钮**：
  - Socket Mode 下，点按钮作为 `type: "interactive"` 的信封从同一条 wss 送来，`payload.type` 是 `block_actions`。
  - 里面有点的人（`user.id`）、频道（`channel.id`）、所在消息（`container.message_ts`）、按钮（`actions[].action_id`、`value`）。
  - 和事件一样按 `envelope_id` 回执，要在 3 秒内，不回执用户会看到报错。
  - pony 照收消息的做法：先落盘再回执，核对和按键放到核心的循环里做。
  - Socket Mode 不需要、也不让填 Request URL。
- **清单**：`settings.interactivity.is_enabled` 从 `false` 改成 `true`。权限、事件订阅都不变：
  - 带按钮的消息照旧用 `chat.postMessage` 发，要 `chat:write`；
  - 按过以后用 `chat.update` 改掉按钮，也只要 `chat:write`，只能改机器人自己发的消息。
- **确认框**：用按钮自带的 `confirm`。标题最多 100 字，正文 300 字，确认、取消按钮各 30 字。
- **用户要做的**：
  1. 在 Slack 应用设置里打开交互：App Manifest 页把 `interactivity` 的 `is_enabled` 改成 `true` 保存，或者在 Interactivity & Shortcuts 页打开。
  2. 页面提示重装就重装一次。重装后到 OAuth & Permissions 页看 Bot User OAuth Token 变没变：变了要在本机更新 `~/.pony/secrets/slack.toml`。只开交互、不加权限要不要重装，文档没找到明确说法，要实测。
  3. 再用 `ranch deploy` 部署新版 pony，它会自己重启 pony。
- **先改 Slack，再部署**：
  - 旧版 pony 收到交互信封只回执、不处理：`chats/slack.rs` 的 `emit_received` 只认 `events_api`，别的类型照样回执。所以先改 Slack 没有坏处。
  - 反过来，先部署新版而没开交互，按钮点了会报错。
- **对现有凭证**：没有影响。Socket Mode 不用 signing secret；不加 token、不加权限，`secrets/slack.toml` 的两个键照旧。
- **接口要加的**（共用核心照旧不写任何一家聊天软件的名字）：
  - `Limits` 加「有没有按钮」；
  - `Outgoing` 加按钮列表，每个按钮带名字、颜色、确认框；
  - `Connection` 加 `update`，用来改掉按钮；
  - `Event` 加 `Action`，就是点了哪个按钮。
  - 没有按钮的平台退回一句话「停」，不给「允许」。

  2. **「框还是那个才按」的原子操作**。核对和按键之间有几十到几百毫秒的空隙。

不改 corral 的办法就是上面这些：pony 这边核对，识别规则写在 pony 里，按家写，像一张小表。

改 corral 的办法有四个。用户的底线是「不要动 ranch 中 corral 的核心代码」，DESIGN §10 把它读作「不改 corral 的代码」，所以四个都碰底线，只列出来交用户定：

  - 改 `hooks.rs`、`events.rs` 和 `status`，属于核心；
  - 只有 Claude Code、Codex 的权限钩子本来带参数；pi、omp 要改采集器、重开 agent；amp、agy 没有。
- **(b) 新加只读命令 `corral screen`**：
  - 命令行把 pen 的输出环按当前窗口大小用 vt100 重放，得到当前画面，复用 `screen.rs`。pen 不改。
  - 结果是近似的：和 R7 升级时的重放一样，改过窗口大小、框早已滚出输出环时会不准。
- **(c) `corral keys` 加 `--instance`**：
  - pen 已经认请求里的实例号，只改命令行；
  - 挡得住「agent 重开过」，挡不住同一个实例里换了框。
- **(d) Claude Code 在框上被拒绝，认出来、回到空闲**（先实测属实再做）：
  - 照 R24 的办法，`blocked` 时也读对话记录末尾，认 `[Request interrupted by user for tool use]`；
  - 改 `events.rs` 里决定什么时候读对话记录的那个条件，属于核心；

  - 没有它，Claude Code 上就做不成「写回答，再说停」。

另外，Claude Code 自己有一条结构化的路：`PreToolUse` 钩子可以带着答案批准提问框和计划（官方文档）。但那等于让 corral 的钩子替人做决定、还要等手机上的回答；corral 的钩子现在只观察、超时 10 秒。不建议走这条。
