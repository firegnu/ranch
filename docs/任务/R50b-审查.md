### 意见

1. **建议改** · `crates/corral/tests/protocol.rs` 的 `terminal_colors_synthetic_agent`（partial 模式只读 1500 毫秒）
   - 问题：合成 agent 读 1.5 秒就停，2 MiB 必须在这段时间里全部经过 PTY。单独跑能过（实测传完 2 MiB 约 0.8–0.9 秒），机器一忙就不够。pen 没有丢字节，是 agent 先停了读。全量 `cargo test` 里 protocol 的测试本来就是并行跑的，以后机器忙时会偶发失败，挡住合并。
   - 复现：先 `cargo test -p corral-core --test protocol --no-run`，再 `for i in 1 2 3; do <target>/debug/deps/protocol-<hash> --exact terminal_colors_reply_bypasses_send_delay_but_never_splits_a_chunk & done; wait`。3 份全部失败，各只收到 1.64–1.69 MiB（`partial: missing or extra bytes`）；同时跑 6 份也是全部失败；单独连跑 3 次都过。
   - 改法：把期望的长度告诉合成 agent（或者让它读到回答的末尾为止）；读够之后再多等一小会儿（比如 200 毫秒），收可能多出来的字节；总上限放宽到 10 秒左右。断言仍然逐字节相等，不放宽。
2. **建议改** · `crates/corral/src/terminal_colors.rs`，`set` 里的 `fs::create_dir_all`
   - 问题：在一台新机器上，如果 `terminal-colors` 是第一条命令（报告里说 paddock 在远端开 agent 前会先调它），`$CORRAL_HOME` 和 `.runtime` 会按 umask 建成 0755。`start` 建这两级目录是 0700，`hooks::helper`、`trust` 建 `.runtime` 也是 0700。之后 `start` 碰到已有的目录不改权限，`~/.corral` 就一直是 0755，本机其他用户能列出 agent 名字。设置文件本身是 0600，颜色不会泄露。
   - 复现：空 CORRAL_HOME 上跑 `terminal-colors --fg '#4c4f69' --bg '#eff1f5'`，`pens`、`pens/.runtime` 都是 `drwxr-xr-x`；main 的 `start` 建出来是 `drwx------`。
   - 改法：照 `hooks::helper` 那样用 `fs::DirBuilder::new().recursive(true).mode(0o700).create(dir)`。
3. **建议改** · `crates/corral/src/terminal_colors.rs` 的 `read`
   - 问题：只查（不带参数）时，如果设置文件里的颜色不合法（比如 `{"fg":"red","bg":"#000000"}`），返回 `{"error":"usage","message":"COLOR must be #rrggbb"}`、退出码 1。调用方什么参数都没给，却报参数错；而且这和旧版「不认识这条命令」用的是同一个 `error`，CONTRACT 写的是前端见到 `usage` 就当作不支持。JSON 本身坏了时返回的是 `"error":"error"`。paddock 只调设置的形式，不读旧文件，不受影响，所以不算必须改。
   - 改法：`read` 里文件内容校验失败时，换成不是 `usage` 的错误（比如 `invalid_settings`，信息里带上文件名）；CONTRACT 补一句只查时文件坏了怎么返回。`start` 的 warning 文字不用动。
4. **可以不改** · `crates/corral/src/pen.rs` 的 `color_replies` 没有上限
   - agent 不读输入、又一直输出 OSC 10/11 查询时，待写的回答会在 pen 内存和升级快照里一直涨，每条约 25 字节。正常 agent 只在启动时问一两次，基本碰不到。真要防，可以像给客户端的输出那样设个上限（比如 64 KiB），超过就不再加新的。
5. **可以不改** · 块与块之间可以插回答
   - 回答只保证不插进一块的中间，块与块之间可以插，比如 `send` 的正文和回车之间、`keys esc` 和下一个键之间。这正是任务和报告要的（不排在带延时的 `send` 后面），真终端也是这样交错的，记一笔就行。
