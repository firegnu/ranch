### 建议改

1. **建议改**：`config.toml` 最后一行没有换行时，绑定一律失败。
   - 位置：`crates/pony/src/core/config.rs:236`（round-trip 比对），`crates/pony/src/core/engine.rs:588`（回复）。
   - 问题：实测 toml_edit 重新输出时总会在末尾补一个 `\n`，所以文件末尾没换行时（行内数组和 `[[slack.channels]]` 两种写法都一样）`document.to_string() != current`，报 `format_not_preserved`。线程里回的是「写配置失败，没绑：format_not_preserved」，像是磁盘出了问题；用户再说多少次结果都一样，只能手改文件。VS Code、Sublime、TextEdit 默认都不补末尾换行，手写的配置出现这种情况并不少见。原文件不会被动到，所以安全上没问题。CRLF、带 BOM 的文件也会这样报，不过在 Mac 上可以不管。
   - 为什么不算必须改：按现在常见的写法（末尾有换行），三步绑定是通的，用例也覆盖了。可是如果用户现在的 `~/.pony/config.toml` 末尾恰好没有换行，「三步，不用手改配置」这一条在这台机器上就没达到。我读不到真实配置，没法确认，所以建议合并前改掉，省得去查。
   - 改法：原文不以 `\n` 结尾时，用 `format!("{current}\n")` 去做 round-trip 比对，也在它上面编辑（写回后只是多了一个末尾换行，内容不变）；改名前比对磁盘时仍然拿原始的 `current` 比。`format_not_preserved` 单独给一句回复，比如「配置文件的格式没法原样保留，没绑；请手动加这一行」，不要归到「写配置失败」。补一条末尾没换行的用例，DESIGN §10 和 README 的说法跟着改。

2. **建议改**：`config.toml` 是符号链接或硬链接时，改名会把链接换掉。
   - 位置：`crates/pony/src/core/config.rs:288`（`persist`）。`load_with_source` 读文件时会跟着链接走，所以链接形式的配置现在是能正常使用的。
   - 问题（实测）：`config.toml` 链到 `dotfiles/pony-config.toml` 时，绑定成功并回「已绑」，但 `config.toml` 变成了一个普通文件（0644，跟着目标文件的权限），链接目标里没有新加的绑定。硬链接也一样会被拆开（nlink 从 2 变 1，另一个路径上的内容不变）。另外，0444 只读的 `config.toml` 也照样会被替换。写进去的内容是完整的，原来那份也还在，所以不算写坏或丢了内容。但如果用户用 dotfiles 链接管理这份配置，之后改的是目标文件，pony 再也看不到；等 stow、chezmoi 之类的工具重新建链接，这次加的绑定又没了，整个过程都没有任何提示。
   - 改法：在 `prepare_binding` 开头用 `symlink_metadata` 检查，不是普通文件或 `nlink > 1` 时拒绝，不写，回「配置文件是链接，没绑；请手动加这一行」。只读文件要不要也拒绝，主控定（拒绝更符合用户把它设成只读的本意）。不建议改成顺着链接写到目标文件：要在目标所在目录建临时文件，还要按目标文件比对，复杂度不值得。

3. **建议改**：运行时重读配置出错、继续用旧配置时，绑定回复会误导人。
   - 位置：`crates/pony/src/core/runtime.rs:107-117`、`:184`。
   - 问题：比如用户改了配置（语义有变），但凭证校验没过，这时 `engine.config_file` 还停在旧原文，而磁盘上已经是新内容。于是 `@pony 绑 x` 每次都回「配置刚被改过，请再说一次」，再说一次还是这句；而 `pony status` 报的是 `config: invalid`。不会写盘，安全上没问题，只是这句话把人引到了错的方向。
   - 改法：在重读的 `Err` 分支里加一行 `engine.config_file = None;`（重读成功时照旧会设回去）。这样回复就是「配置现在有错，没绑；请先修好配置」，和 status 对得上。这一行不碰重连逻辑。

### 可以不改

4. **可以不改**：多行数组里新加项的排版。`config.rs` 往行内数组 `push`：带尾逗号时，新项接在上一项的同一行，原来的行尾注释被挤到新项后面；不带尾逗号、末项后面有注释时，新项会写成下一行的 `, { id = "...", repo = "..." }]`。实测两种都是合法 TOML，重读结果也对，只是不好看。
5. **可以不改**：绑定的各种拒绝和写盘失败只在线程里回，不写日志。DESIGN 的日志规则是要记错误码的，以后排查时只能去翻 Slack。可以加一行 `bind_failed <code>`（经过 `safe_code`）。
6. **可以不改**：`runtime.rs` 里 `config_file` 的更新没有直接的用例，引擎用例是用 `reload_binding_config` 模拟重读。我逐行对过代码：`config_file` 只在新配置被采用（或语义相同）时，和 `active`、`engine.configs` 在同一轮里一起换；`open_corral`、`connect` 出错时 `serve` 直接返回，不会留下对不上的状态。

### 重点看的几项，核对结果

- **写配置**：在同一目录建临时文件，写入，设成原文件的权限，`sync_all`，改名前再读一次磁盘、和正在用的原文比对，然后改名。候选内容是在「磁盘当前内容 == 正在用的原文」的前提下生成的，所以不会拿旧原文盖掉用户刚改的内容；剩下的空档只有最后一次比对到 `rename` 之间，不加锁做不到更好，可以接受。文件中途被删掉时回「刚被改过」，临时文件随 drop 删除。除了第 1、2 条，下面这些写法实测都能正确追加，重读结果也对：两种 `channels` 写法、`slack = { ... }` 行内表、`slack.channels = [...]` 点号键、`[[slack.channels]]` 写在 `[slack]` 前面。
- **`config_file` 和正在用的配置**：只改注释时，`next == active` 分支会换成新原文；配置有错时 `parse` 先失败，回「配置现在有错」；凭证校验失败的情况见第 3 条。不会出现拿新原文配旧配置的情况，重复绑定的检查用的是 `engine.configs`，候选内容还会再过一遍完整校验，兜住了重复。
- **公开频道**：只有 `Ok(Some(true))` 才往下走，`Some(false)`、`None`、`Err` 都会回话并返回。`ConfigFile::bind` 只有这一处调用，在检查之后。连接不在表里时报 `disconnected`，这在实际运行中走不到（`connect` 失败时 `serve` 直接退出）；Socket 断着时 `channel()` 走 HTTP，失败也回「查不到」。公开频道的检查排在重复检查前面，所以在公开频道里不会说出别的频道名。没找到绕过这项检查的路径。
- **只认 owner、已绑频道**：owner 检查在未绑分支之前，别人发这句不回、不送、不查频道、不调 status；已绑频道里 `@pony 绑 x` 照旧整句送给 `<仓库>/main`。两种情况都有用例。
- **不漏东西**：回复里只有固定的句子、用户打的且已经校验过的仓库名、频道名或 ID，以及经过 `safe_code` 的错误码；不带路径、配置内容和适配器的原始错误。没有新增日志和凭证读写。共用核心的源码里没有平台名，`crates/corral/` 和 `crates/pony/src/chats/` 都没有改动。`?` 的状态行抽成 `agent_summary` 复用，退出码 2 时跳过的行为没变。
