## 要摸清的

1. **一个 coding agent 至少要有哪些部分**：调模型和工具的循环、读写文件和改文件的办法（整文件写、按行替换、diff）、跑 shell、上下文太长时怎么压缩、会话存盘和接着聊、权限确认、中途被打断（Esc）、子任务或子 agent、技能、MCP。哪些是第一版必须的，哪些可以后补。
2. **能借鉴的开源实现**：重点看 Codex CLI（Rust，服务端、TUI、app-server 都有），哪些模块的做法能参考、哪些能按许可证直接用；再看 pi、omp、opencode 各自哪几块写得好。写代码量大概多少、许可证。只读源码和文档，不改它们。
3. **模型怎么接**：Rust 没有官方 SDK，比较社区的库（成熟度、维护情况）和自己写 HTTP + 流式解析的工作量。Anthropic、OpenAI 的接口，OpenAI 兼容接口（opencode 那些模型、以后本机或 5090 上的开源模型）。登录和计费：用户现在的 Claude Max、ChatGPT 订阅能不能给自己做的 agent 用，还是只能用按量计费的 API key（要查各家现行条款，写出处和日期）。这条决定用起来花不花钱。
4. **一个服务端、多个客户端**：agent 的核心（会话、调模型、工具、权限）做成服务端；终端客户端、corral、以后的桌面应用和网页都是它的客户端。要摸清：
   - 协议用什么：HTTP + SSE、WebSocket、JSON-RPC。重点比较 opencode（服务端走 HTTP、事件走 SSE，终端客户端连上去）和 Codex 的 app-server（会话 → 一轮 → 一条条项目，JSON-RPC）两种分法，给出自定协议的建议。
   - ACP（Agent Client Protocol，Zed 提的）只作对照：用户不看好；它是编辑器把 agent 当子进程拉起、一对一走标准输入输出，没有一个服务端多个客户端、远程连接和认证。写清它哪里不合适，以及要不要以后单独做一层转接给编辑器用。
   - 单独发布的桌面应用怎么带服务端：随应用一起装、自己拉起本机服务端，还是连已经在跑的那个。
   - 服务端怎么起：在任何终端里敲一个命令，是自动在后台起服务端再连上，还是同一个程序里带着服务端；一台机器一个服务端还是每个会话一个。
   - 几个客户端能不能同时看同一个会话（比如终端里在跑，手机网页上也能看、能批准）；只听本机还是也能远程连，远程时怎么认证。
   - 协议里要有哪些消息，才能让客户端显示流式回复、工具调用、权限框、提问框、打断。
5. **独立，但能接进 corral**：agent 本身不依赖 ranch、corral、paddock、cairn，单独装、单独用。corral 那边怎么接它：照现有六家写一个适配器（corral 在终端里开它的客户端，靠它报的事件知道状态）；还是 corral 直接当它的一个客户端连服务端，拿到结构化的状态（开始干活、调用工具、这一轮结束、等批准或等回答、被打断、回复原文），不用钩子或读屏去猜。带首句启动、免确认启动、退出。
6. **和 ranch 其他部分的关系**（都是可选的，不接也能单独用）：两份技能（corral、corral-dispatch）从哪读；能不能进 fence 的 sandbox；派活分工表（R31、R34）里怎么放；pony 的按钮（提问选项、拒绝、允许）能不能直接靠它报的结构化数据，不读屏。
7. **放在哪、用什么做界面**：既然不和 ranch 绑死，倾向单独一个仓库，确认有没有理由放进 ranch。终端客户端怎么做（要不要全屏界面；Rust 的 TUI 库比较，比如 ratatui；ranch「不依赖 ratatui、crossterm」那条只管 ranch 仓库）；服务端的 HTTP、SSE 或 WebSocket 用哪些库；网页客户端用什么做、谁来起网页服务。只列选项和取舍，不定。
8. **分期和工作量**：照用户定的次序：第一期服务端加终端客户端，在任意终端里开、能干一件小活；第二期接上 corral 这一套（paddock、pony 看得到状态，能派活）；之后单独发布桌面应用、网页客户端、多客户端同看一个会话等。给第一期要做的清单和大概工作量，后面几期列要点。
