### R1｜必须改：继承环境的嵌套 amp 仍会写父 agent 的事件

位置：`crates/corral/resources/amp_plugin.ts:10–24`，`crates/corral/src/agents/mod.rs:135–143`。

问题：这两项环境检查只能区分种类，不能确认“这个 amp 是 pen 启动的那个 amp”。corral 管的 amp 再以继承环境的方式运行一个 amp 时，后者仍带着父进程的 `CORRAL_KIND=amp`、`CORRAL_EVENTS`、`CORRAL_INSTANCE` 和 `CORRAL_CWD`；插件加载就往父事件文件写 `SessionStart(amp-startup)`。不需要等子 amp 发第一句，父 agent 的主会话就会被换掉；随后子 amp 的顶层 thread 也没有跨进程的 `parentThreadID` 可供过滤。这里说的是直接运行的嵌套 amp；再次通过 `corral start` 启动会重建环境，不属于此问题。

证据：入口与无条件启动事件由代码直接确定；用对应的 v1 事件在隔离目录回放，`T-main` 工作中收到另一次插件加载的 `SessionStart(amp-startup)` 后，主会话变为 `amp-startup`、状态变为 `idle`，之后 `T-main` 的 Stop 留在 pending，未被应用。这是环境继承条件下的静态路径加事件回放，没有运行真实 amp。

改法：把插件入口校验绑定到 pen 实际启动的 amp 进程身份，未确认归属就不注册、不写事件；仅再加一个同样会被子进程继承的名称或 token 不足以区分两者。补一个“父 amp 环境被另一个 amp 进程继承”的合成检查，确认第二个插件实例不能写父事件文件。

### R2｜必须改：等待安装确认后仍按旧计划写删，会覆盖或删除用户文件

位置：`crates/corral/src/integration.rs:155–197`。

问题：`plan()` 在询问用户之前检查归属；用户回答后，直接 `remove_file` 或 `rename`，没有再检查路径及文件。等待期间若同名文件被用户的配置同步程序换成非 corral 文件，安装会覆盖它，卸载会删除它；若 `plugins` 目录被换成符号链接，还会写删链接目标里的文件。同目录临时文件保证写入内容的原子性，不能保证旧的归属判断在确认后仍成立。

证据：Rust 临时探针给被审查二进制提供 PTY，在读到 `[y/N]` 后替换文件，再回答 `y`。install、uninstall 均退出 0、`written:true`，用户文件均未保留；在提示后改成目录符号链接的两种操作也均复现。所有目标都在探针自己的临时 HOME 内。

改法：确认后重新检查计划和文件归属；目标或父目录变化就中止，不沿用旧计划。实际写删还应固定并校验父目录和目标身份；`create` 不能无条件覆盖刚出现的文件。补上上述确认窗口内换文件、换目录的回归检查。

### R3｜必须改：查询父 thread 失败时反而把子 thread 永久认成主会话

位置：`crates/corral/resources/amp_plugin.ts:31–38`，结合 `crates/corral/src/events.rs:97–130`。

问题：`parentThreadID()` 抛错或拒绝时，错误分支返回 `true`，并把结果留在 `threads`。于是一次子 thread 查询失败就会产生带相同 cwd 和 `has_transcript:true` 的 SessionStart，替换真正的主会话。原来的主 thread 已经在缓存里，之后不会再发 SessionStart 恢复身份；它的输入和回复持续被放进 pending。这个错误分支会造成持续的送达确认失败，不只是短暂的状态偏差。

证据：按这个分支会输出的事件回放：主 thread 开始 → 子 thread 被当作顶层开始并结束 → 主 thread 结束并收到下一句。实际 `main_session=T-child`、`state=idle`、`reply=child reply`，主 thread 的 Stop 和下一句输入都在 pending。

改法：无法确认父子关系时不发布该 thread 的事件，也不要把失败永久缓存成“顶层”；后续事件可以重试确认。补查询拒绝后仍能处理主 thread 输入、结束和回复的检查。记录失败应只损失该次观测，不能夺走主会话身份。

### R4｜必须改：切回已经访问过的 thread 后，状态机仍指向另一个 thread

位置：`crates/corral/resources/amp_plugin.ts:26–40,63–67`。

问题：SessionStart 只在第一次 `watch(id)` 时写出，`session.start` 处理函数本身不重新建立当前会话。因此正常的 A → B → A 切换中，第二次进入 A 时直接复用缓存，corral 的主会话仍为 B。A 接下来的输入和 Stop 不被处理，`reply` 返回 B 的回答，新的 send 也拿不到 A 的输入确认。Amp 官方说明 `session.start` 会在打开或切换已有 thread 时触发，同一个 CLI 还可同时运行多个 thread；这不是假设一个不存在的生命周期事件。[Amp 插件生命周期文档](https://ampcode.com/docs/customize/plugins)（查阅：2026-10-14）。

证据：回放 A 完成、B 完成、切回已缓存的 A 并完成第二轮，实际 `main_session=T-B`、`reply=B reply`、`input_count=2`，A 第二轮的两条事件均在 pending。

改法：把“是否为子 thread”的缓存和“当前主会话”的选择分开；合法的主 thread 再次被激活时要恢复其会话身份，并防止后台 thread 的事件抢占。补 A → B → A 后输入能确认、回复属于 A 的回归检查。

### S1｜建议改：明确旧、新 CLI 混用 amp 的边界和处理次序

位置：`docs/DESIGN.md` §7、`docs/任务/R6-接入amp.md:83–86`，相关实现为 `crates/corral/src/cli.rs:132,249–255`。

问题：现有四家和 pen 协议的双向兼容成立，但 amp 不能直接套用这一结论。隔离的模拟 pen 验证：同一份 amp 工作中事件，新 CLI 报 `working`，`653c5b2` CLI 报 `unknown`；旧 `wait` 返回 `unknown`，旧 `send` 绕过已知 agent 的 idle 检查并返回 `confirmed:false`，同条件下新 `send` 拒绝为 `not_idle`。另一方向，旧 corral 把 amp 当普通程序启动时没有 `CORRAL_KIND`，新 CLI 读取这种没有插件事件的 pen 会一直报 `starting`、send 退回 7；单独 upgrade pen 不会给已启动的 amp 补上环境变量。

改法：写明 amp 的 status/wait/send/reply 要使用 R6 入口，检查固定旧路径的调用方和旧提醒；旧 corral 启动的 amp 如要转成受支持的 amp，需要经用户安排重新启动。说明这与现有四家“不必升级 pen”是两回事。若要保证旧入口对 amp 也有完整语义，需另行明确实现及验证范围，不能只用四家兼容测试作证明。

### S2｜建议改：技能里的“start 完马上 send”没有就绪保证

位置：`crates/corral/resources/SKILL.md:22`、`AGENT_USAGE.md:18–20`、`crates/dispatch/resources/corral-dispatch/SKILL.md:187`、`docs/CONTRACT.md` 的 amp 首句说明；相关实现为 `crates/corral/src/pen.rs:873–880`。

问题：start 在 pen 和子进程建立后就输出成功，没有等待插件的 SessionStart。即使已经安装插件，紧接着 send 也可能遇到 `starting` 并退回 7。当前技能直接进入 send，且把持续 starting 归因于未安装；CONTRACT 还承诺“一起来就报 idle”。插件加载、启用失败或旧进程未重开也会造成 starting，不能仅凭这一状态认定没装。

改法：技能先等待明确就绪，再发第一句；把“未装”改为需要检查的原因之一，提醒安装后要重开已有 amp。文档不要承诺 start 的返回等于插件已就绪。这里建议修正调用说明，不要求扩大到通用启动机制。

### S3｜建议改：说明符号链接检查到哪一层

位置：`crates/corral/src/integration.rs:120–122`、`crates/corral/src/skills.rs:25–37`、`docs/CONTRACT.md` 的 foreign 定义。

问题：检查在 `amp` 配置目录处停止，不检查上面的 `.config` 或 `XDG_CONFIG_HOME` 本身。临时 HOME 中把 `.config` 链到另一目录，install 实际报 `create`、`written:true` 并在链接目标下写入；文档目前笼统说“路径上的符号链接”都属于 foreign。文件、plugins、amp 这三层的链接会被拒绝，根目录这一层却例外。

改法：明确配置根目录是否允许链接。如果允许，缩小文档的 foreign 表述并补检查；如果不允许，把检查边界上移到配置根目录。与 R2 不同，这一项是既有配置根目录的边界约定，未复现对该根目录内其他文件的覆盖。
