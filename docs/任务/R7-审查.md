### R1｜必须改：终端缩窄截断宽字符后，读屏 panic 会杀掉 pen 和 agent

- **位置**：`crates/corral/src/screen.rs:9–22`；调用处 `pen.rs:291–292、548–550、640–641`；后果见 `pen.rs:207–220`。
- **问题**：`vt100 0.16.2` 的解析直接运行在 pen 主循环里，没有故障隔离。最小复现是 2×5 屏幕写入 `ab中`，缩成 2×3，再喂 `x`：宽字符剩下第一格，vt100 在 `screen.rs:870` 对不存在的下一格 `unwrap()`。这不只是 debug 的算术检查：临时副本的完整 pen 探针在 **debug 和 release 都复现**。假程序先输出 118 个 `a` 加一个 `中`，由附着协议把终端从 120 列缩到 119 列，再输出 `x`；随后 `status` 返回 `not_found`，记录的 agent PID 已不存在，`pen.log` 留下上述 panic。`Pen::drop` 在 owner 路径直接 SIGKILL agent 进程组。另有 1 列屏幕喂宽字符的边界也会 panic；现有 `max(1)` 并不能保证解析安全。
- **改法**：让读屏故障只废弃这份屏幕、退回钩子状态，不能退出 pen；保护范围要覆盖增量 feed、resize、从输出环重建以及取文字，解析器 panic 后不能继续复用失效对象。补入宽字符截断和窄屏的回归，至少验证 pen/agent 存活、PTY 仍可读写，不能只断言解析器不报错。不要只修本例而仍让其他解析异常越过兜底边界。

### R2｜必须改：未闭合 OSC 会绕过输出环上限，无上限占用解析器内存

- **位置**：`crates/corral/src/screen.rs:10、14–15`，`pen.rs:640–645`；锁定依赖 `vte 0.15.0` 的 `src/lib.rs:55–64、544–557`。
- **问题**：vt100 带入 vte 的默认 `std` 特性，OSC 缓冲是没有长度限制的 `Vec<u8>`；源码中的 1024 字节常量只约束非 std 配置。屏幕不开 scrollback、ring 只留 512 KiB，都限制不了这个缓冲。用原样复制的 `screen.rs` 和当前依赖做限量分配探针：40×120 屏幕先喂 `ESC ] 52 ; c ;`，之后以 64 KiB 一块持续喂 ASCII、不结束 OSC；累计输入 1/4/16 MiB 时，解析器新增的在用堆内存分别是 2/8/32 MiB，屏幕文字一直为 0 字节。最后补 `ESC \`，32 MiB 容量仍保留。持续异常输出可以继续增长，造成 pen 内存耗尽；**本次只验证到 16 MiB 输入，没有把机器或 pen 压到 OOM**。这是确定的无界缓存路径；R1 的 panic 捕获也挡不住分配失败导致的进程终止。
- **改法**：对读屏解析的单条控制序列设置明确的资源上限，超限后丢弃该序列或停用本次读屏，同时继续转发原始 PTY 和维护原有状态；不要依赖 ring 截断来约束解析器。补分块未闭合 OSC、长 OSC 结束后的回归，验证内存有界且 pen/agent 仍工作。

### S1｜建议改：把升级重放的精度边界说清楚，并覆盖改大小和环截断

- **位置**：`crates/corral/src/pen.rs:548–550`，`screen.rs:78–84`，DESIGN §7「读屏兜底」。
- **问题**：现有重建测试只是同一尺寸、完整历史按不同分块喂入，并没有验证真实 ring 被截断或历史中改过尺寸。临时 pen 探针先显示 `abcdefgh`，缩窄到 4 列后当前文字是 `abcd`；成功 upgrade 后按当前 4 列重放旧字节，文字变成 `abcdefgh`，agent 没有输出新内容。另一个限量探针显示 `Allow?` 后输出 512 KiB BEL，原屏幕仍有提示，但截断后的 ring 重建为空。这些会造成短暂或持续到重绘的状态偏差，不能保证任意情况下重建完全一致。
- **改法**：补这两类合成用例，明确“从最后一段输出近似恢复，受历史尺寸和截断影响”的边界；接 agy 时按真实重绘方式决定是否触发重绘或暂缓使用重建结果。本意见按任务的状态精度边界列为建议，不要求这一轮另建屏幕快照协议。

### S2｜建议改：最下面 n 行目前数的是逻辑行，不是屏幕行

- **位置**：`crates/corral/src/screen.rs:20–22、34–42、71–74`。
- **问题**：vt100 的 `contents()` 会拼接自动折行，和 `text()` 注释的“一行对应一屏幕行”不同。4×6 屏幕输入 `Allow?abcdef`，物理上第一行是 `Allow?`、第二行是 `abcdef`，返回的文字却是 `Allow?abcdef`；`rows: 1, all: ["Allow?"]` 因而命中最下面一行以外的提示。宽度变化也会改变这类规则的有效观察范围。
- **改法**：在写 agy 规则前定清行的语义。若仍按设计的屏幕行计数，使用 vt100 的逐行接口，再过滤空白行、取末 n 行；若有意按拼接后的逻辑行匹配，改清注释和设计，并补上述折行用例。作为规则精度建议处理，不阻塞于这一细节。
