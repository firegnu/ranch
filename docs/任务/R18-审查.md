## 审查意见

改完再合并：必须改 3 条，建议改 1 条。审查基于 `b9aede1e90e429fa9daaeac74bc02c4f07c7494f`。

1. **必须改：pen 查询失败会把已经设定的档案静默丢掉。**
   - 位置：`crates/corral/src/child_sandbox.rs:13–15`；相关错误转换在 `crates/corral/src/state.rs:183–202`。
   - 问题：`state::require` 的所有错误都返回 `Ok(None)`，包括超时、协议不兼容、坏回复，而这些不能证明调用者已经退出。主控的疑点成立，会违反“设了就要么生效、要么报错”。尤其 `request_timeout` 连读取超时也转成 `not_found`，因此只改为“吞掉 not_found，其他报错”仍堵不住。
   - 实测：隔离目录内起 `/bin/cat` 父进程，设定 `dev`，读出其 pen PID 后仅对这个 PID 发 `SIGSTOP`；带父进程的 `CORRAL_NAME`、`CORRAL_INSTANCE` 执行不带显式 sandbox 参数的 `start`。约 **30.034 秒**后返回 `ok:true,sandbox:null`，子 `/bin/cat` 实际运行；父 agent 仍活着，恢复 pen 后查询仍为 `child_sandbox:{"profile":"dev"}`。测试随后恢复并停止了所有合成进程。
   - 改法：区分“确认已退出／旧 instance”与“无法确认状态”。对可能属于当前运行的设置，通信失败必须明确报错且不起子 agent，不能退回无墙；可结合本地记录、instance 和现有运行锁判断，保留确实退出或旧 instance 的默认行为。补这个定向回归，并在 CONTRACT 写明状态无法确认时的错误。无需给旧 pen 增加协议操作。

2. **必须改：旧 instance 的慢设置请求能覆盖新 instance 已成功保存的档案。**
   - 位置：`crates/corral/src/child_sandbox.rs:49–62`。
   - 问题：只在 fence 检查之前取一次 instance，检查完成后直接覆盖同名目录中的文件。原子 rename 只保证文件完整，不能防止旧运行的请求覆盖新运行的设置。随后读取发现 instance 不匹配便当作没设，新运行已设好的墙因此失效。
   - 实测：用假 fence 暂停旧父进程的 `child-sandbox test/parent slow` 检查；停掉父进程、同名重开，并成功设定 `dev`；放行旧检查。旧请求返回成功并写回旧 instance，新父进程查询从 `{"profile":"dev"}` 变成 `null`，随后以新 instance 发起的 `start` 返回 `ok:true,sandbox:null`。
   - 改法：让设置／清除的提交对同名并发写入有保护，并在受保护的提交阶段确认仍是目标 instance；或按 instance 隔离记录，使旧请求不能覆盖新运行的记录。不能只在无保护的写入前再查一次、留下同类检查与写入之间的竞争。旧请求发现重开时应报错，保留新设置；补上述可控制检查进度的回归。

3. **必须改：旧 CLI 清理后的残留不会被新版 `ls` 清理，兼容说明不准确。**
   - 位置：`docs/CONTRACT.md:162、175`；`crates/corral/src/state.rs:240–247、278–284`。
   - 问题：旧 CLI 不认识 `child-sandbox.json`，但会删除 `lock`。新版 `list()` 只把有 `lock` 的目录加入待处理列表，因此之后的新版 `ls` 无法发现这个残留目录。CONTRACT 的“agent 退出后由新版 ls 随目录清理”“留待下次新版 CLI 清理”缺少这一限制。
   - 实测：新 CLI 起隔离 `/bin/cat`、设 `dev`、停止；用已安装的旧版 `versions/7fbb76d/bin/corral ls` 操作同一个隔离 CORRAL_HOME，再运行本次编译的新版 `ls`。两者都返回空列表，`lock` 已不存在，`child-sandbox.json` 仍存在。
   - 改法：若维持任务书的后续新版清理承诺，补上对这类无 lock 残留的安全发现与清理，不能误删正在启动的目录；若决定不补清理，则必须将 CONTRACT 改为准确说明“新版 ls 也不会清这个残留；同名用新版 start 重开时才清掉”，并由主控确认这处任务实现取舍。instance 隔离能避免误用，不能证明残留已经清理。

4. **建议改：没有设置文件也先等待一次最长 30 秒的父 pen 查询。**
   - 位置：`crates/corral/src/child_sandbox.rs:13–19`。
   - 问题：这是第 1 条之外的默认路径退化。没有 `child-sandbox.json`，但环境带着父进程身份时，仍先查询 pen。未设档案的隔离父 pen 暂停后，子 `start` 实测等待 **30.041 秒**才按默认行为成功；原来的 start 不依赖父 pen 响应。
   - 改法：对没有记录的默认情况采用不访问 pen 的快速路径；读取到了可能生效或损坏的记录，再做必要的实例／存活判断。保留明确的读取时点语义，不能为解决延时重新引入第 1 条的漏套墙。
