### 必须改

1. **必须改：卸载会删掉不属于 corral 的换行，把两行粘成一行。** 位置：`crates/corral/src/integration/block.rs` 的 `apply`，卸载时的 `bytes.drain(range)`。
   - 问题：`range` 总是包括块前面那个 `\n`，但这个换行不一定是 corral 加的。只要原文件末尾没有换行（或者用户删了块前的空行），而块后面又有别的内容，卸载就会把块前一行和块后一行接成一行。违反「卸载只删这一段」，并且写坏 TOML，用户自己开的 Kimi 也读不了这份配置。
   - 复现（隔离 HOME，本分支 `debug/corral`）：
     - `printf 'default_model = "mine"' > $HOME/.kimi-code/config.toml` → `corral integration install --agent kimi --yes` → `printf '[extra]\nk = 1\n' >> config.toml` → `corral integration uninstall --agent kimi --yes`。结果文件是 `default_model = "mine"[extra]` 加 `k = 1`。
     - 原文件末尾有换行，用户删掉块前的空行，再在块后追加同样内容：结果相同。
     - 块后紧接着一个 herdr 风格的块（`# >>> herdr kimi integration` …，前面不带空行）：卸载后变成 `default_model = "mine"# >>> herdr kimi integration`，herdr 的开头标记跑到了上一行。
   - dev 的 `kimi_installs_and_removes_only_its_marked_block` 往块后追加的内容正好以 `\n` 开头，所以没测到。
   - 改法：只在三种情况下连前置换行一起删：块在文件开头，块前一个字节是 `\n`，或者块在文件末尾。其他情况只删 `# >>> …` 到 `# <<< …\n`。补一条测试：原文件没有末尾换行，块后追加 `[x]\n`（前面不带换行），卸载后每一行都完整。CONTRACT 里「卸载也删除 corral 为该块添加的前置换行」按新规则改一句。

2. **必须改：`workdir_key` 和 Kimi 2.3 的 `encodeWorkDirKey` 结果不一样，部分目录下状态和回复全错。** 位置：`crates/corral/src/agents/kimi.rs` 的 `workdir_key`。
   - 问题：Kimi 的写法是 `replaceAll(/[^a-z0-9._-]+/g, '-')`（`packages/agent-core-v2/src/_base/utils/workdir-slug.ts`@684bae9），每一段连续的不允许字符都换成一个 `-`，不看前面是不是已经有 `-`。corral 的写法是前面已经是 `-` 就不再加。于是目录名里出现「允许的 `-`，紧跟不允许的字符，后面还有字」时两边结果不同。例如 `foo - bar`：Kimi 得 `wd_foo---bar_…`，corral 得 `wd_foo--bar_…`。`a-(b)`、`my-项目x` 也不一致。
   - 后果：钩子记下的 `transcript_path` 指向一个不存在的 wire。第一句之后 `status` 一直是 `working`，`wait` 等不到 `idle`，`reply` 永远报 `no_reply`，批准框只能靠读屏发现。
   - 复现：临时单测里拿 6 个目录名对照（期望值用 node 跑同一段 TS 算出），其中 3 个不一致，就是上面 3 个。
   - 改法：照 Kimi 的正则改成「每一段连续的不允许字符换成一个 `-`」（例如进入一段新的不允许字符时 push 一个 `-`，不看 slug 末尾是什么）。trim、截 40 个字符、再 trim 的顺序不变。加一条对照测试，写死上面这几个目录名（含空格、括号、中文）和 Kimi 算出的值。

### 建议改

3. **建议改：`wire_events` 每次查状态都从头读整个主 wire（主控记的那条）。** 位置：`kimi.rs` 的 `wire_events`。
   - 是否成立：成立。临时测试用 50 MB 的合成 wire（一半是会被跳过的行，一半是要解析的 `tool.result`），release 版每次 status 大约 37 ms，耗时随文件大小线性增长。
   - 严重程度：`corral wait` 每 200 ms 调一次 status，paddock 轮询和 `after` 也会调。长会话的 wire 到几十 MB 时，会持续占 CPU、让 `wait` 变慢。不影响结果对错，所以不算必须改。
   - 改法：在 cursor 里记下 wire 的 (dev, ino, 已读 offset) 和本轮的 turn、文字、状态，下次只读新增的部分。inode 变了、文件变短了或 `turn_started` 变了，再从头读。顺手把逐行的 `from_utf8_lossy` 换成按字节查找。

4. **建议改：最后一步 KILL 之后，pen 等子树清空没有上限。** 位置：`pen.rs` 主循环退出条件里的 `stop_tree.is_empty()`。
   - 问题：子树里只要有一个进程停不掉，pen 就一直留在主循环，每 50 ms 扫一次进程表。停不掉的例子：对它发信号报 EPERM（比如 Kimi 跑的 `sudo …`，子进程以 root 身份运行），或者进程卡在不可中断的等待里。扫表开销不大（本机 993 个进程，每次约 0.6 ms），问题是 pen 不退出：`corral stop` 90 秒后报 `timeout`，名字一直被占着，只能按 PID 去杀 pen。
   - 这条没写复现，因为要造出 root 进程。
   - 改法：KILL 之后最多再等几秒（比如 3–5 秒），还有残留就把剩下的 PID 写进 pen.log 和 exit.json，然后退出。CONTRACT「父进程先退也等子树清理」补上这个上限。

5. **建议改：`block.rs` 的单测在 macOS 上没测到它要测的分支。** 位置：`a_shared_file_changed_after_planning_is_never_written`，以及 `apply` 里的符号链接检查。
   - 问题：`apply` 做符号链接检查时，目录是用环境变量 `HOME` 重新算的。单测把 `g.dir` 换成了临时目录，`linked()` 于是一路查到 `/`，碰到 `/var -> private/var`，报的是 `configuration became a symbolic link`。`is_err()` 因此成立，「判断之后文件被改」那条比对分支根本没执行。
   - 实现本身没问题：我在 `/private/tmp` 下另写临时测试，内容被改、内容相同但换了 inode 两种情况都报 `configuration changed`，什么都不写，0640 权限也保留了。
   - 改法：测试用 canonicalize 过的临时目录，并断言错误信息是 `configuration changed`。`apply` 改用 Plan 里记下的目录做符号链接检查，不要再读一遍 HOME。

6. **建议改：回复把整轮所有 step 的文字直接拼在一起。** 位置：`kimi.rs` 的 `wire_events`。
   - 问题：Kimi 的 `content.part` 是按 step 写的（`loopService.ts` 的 `stepCompleted`，每个 part 都带 `step`）。一轮里有工具调用时，工具前的说明和最后的回答会被接成一串，中间没有分隔。例如工具前是 `I'll check the file.`，工具后是 `The port is 8080.`，`reply` 得到 `I'll check the file.The port is 8080.`。别家的 `reply` 是最后一条助手消息，pony 和派活都把 `reply` 当最终答复用。
   - 改法：只保留最后一个 step 的文字（出现新 step 的文字时先清空），或者各 step 之间加空行。CONTRACT 里写清楚取的是哪种。

### 可以不改

7. **可以不改：子树可能收进 Kimi 正在开的另一个 agent。** 子树收录的是「停止时还是 Kimi 子孙」的进程。如果 Kimi 正在跑 `corral start`（新 pen 在报告就绪之前还是 `corral start` 的子进程），这时去停 Kimi，新开的那个 agent 的 pen 和 agent 会一起被停掉。窗口很短，而且阶段 1 的 Kimi 不当主控。阶段 2 让 Kimi 派活时，再考虑把 corral 的 pen 排除在外。
8. **可以不改：降级时旧 pen 会丢掉新字段。** 从新版 `corral upgrade` 换回旧版时，旧 pen 不认识快照里的 `pending_prompt` 和 `stop_tree`，还没送出的首句会丢，正在进行的停止也会失去子树跟踪。只在降级时才会发生。
9. **可以不改（和本任务无关）：主控遇到的那次 `protocol` 测试失败是原有的测试竞态。** `injected_hooks_use_the_namespace_entry_and_adapter_arguments_are_preserved` 的合成程序是 `printf … > "$CORRAL_EVENTS.args"`，shell 先建出空文件再写内容，测试在 `eventually(exists)` 之后立刻读，可能读到空的或写了一半的内容。本分支没改这个测试，也没改它涉及的代码。

### 重点各项的结论

1. **会不会写坏用户的 Kimi 配置**：除第 1 条外，块外字节不变（CRLF、末尾没有换行、块后追加以换行开头的内容，这几种都对）；权限保留（实测 0640）。以下情况一律不写：标记缺一半、标记重复、块被改过、配置文件或配置目录是符号链接、判断之后文件被改（包括内容相同但换了 inode）。写前重读比对和同目录原子改名都成立；新建文件用硬链接，不会覆盖。不会把 herdr 的标记认成自己的；herdr 只受第 1 条卸载换行的影响。
2. **停止会不会误杀或停不干净**：只对 Kimi 生效。子树按 PID 加出生时间核对，PID 被复用也不会打错进程。Kimi 先退出、子孙被 launchd 收养后，仍按记下的身份跟踪，到 KILL 那一步杀掉。别家的停止步骤、进程组信号和退出条件都没变。`Drop` 里的 SIGKILL 只在有停止子树时才发，交接中（Handoff）不发；`stop_tree` 进快照，新 pen 接着停；standby 用 `_exit` 退出，不会触发 Drop。有问题的地方见第 4、7 条。
3. **状态算得对不对**：
   - 子 agent 不影响主会话：子 agent 的钩子事件不改状态（非 user 来源的 TurnStarted 直接丢弃，其余事件只记成 `Kimi:*`）；子 wire 不读；主 wire 按 agentId=main、turnId 和时间过滤。
   - idle 和回复：只有主 wire 写了 `completed` 才转 `idle` 并给回复；每次查状态先清空 reply，所以新一轮还没完成时 `reply` 报 `no_reply`。
   - Esc：提问框上的 Esc 只产生 `interaction.resolved`，状态回到 `working`；运行中的 Esc 产生 `turn.ended cancelled`，状态是 `interrupted`。`turn.ended` 的四种 reason（completed、cancelled、failed、blocked，对照 `turnOps.ts`）都有处理。
   - 就绪判断的排除词对照源码都是真实文字：`Trust this folder?`、登出时的 `Run /login …`、`Select a model`。
   - `observe_transcript` 的改动不影响别家：别家的 `transcript_events` 返回空，`transcript_interrupt` 只读不写，写 cursor 的条件和原来等价，Claude Code 的 R24、R43 打断判断不受影响。
   - 有问题的地方见第 2、3、6 条。
4. **全局钩子的门控**：用本分支 corral 实测了三种情况：用户自己开的 Kimi（没有 `CORRAL_*`）、`CORRAL_HELPER` 不存在、有 helper 但父进程不是 pen。三种都是空输出、退出码 0、不记事件。Kimi 对非 0 退出码（2 除外）和非 JSON 输出一律放行（`runHook.ts`），空输出就是允许。`__hook agy:*`、`__hook amp:*` 和未知种类仍输出 `{}\n`。
5. **公开格式和兼容**：CONTRACT 和实现一致，只差第 1、4 条要补的两句。`install.format` 只出现在 kimi 那一项，是兼容新增，amp、agy 的输出不变，paddock 现有用法不受影响。旧版 corral 把 kimi 看成 `unknown`，`integration` 也不列它，不会出错。pen 快照的新字段带 `serde(default)`，新 pen 读旧快照没问题。

### 第 3–6 条的改动有没有引入新问题

- **第 3 条（wire 增量读）：改对了，但有一处小的性能退步（见下面新问题 1）。**
  - 逻辑：cursor 里存路径、dev、ino、文件长度、最后一个完整行的 offset、`turn_started`，以及本轮的 turn、step、文字、工具、交互、最新状态。半行不推进 offset。路径或 inode 变了、文件变短了、`turn_started` 变了，就从头重读。新一轮一定从头读，这是对的：先查的那次可能已经把新一轮的 `turn.prompt` 读进了旧的累积结果里。
  - cursor 里新增的 `kimi_wire` 不会出现在任何公开输出里；没有新内容时 cursor 前后相同，不会重写文件。
  - 我补的临时测试：同一个 `turn_started` 下换成另一个会话的 wire，不会带上旧会话的文字；wire 文件消失时不报状态、不给回复，文件回来后能接着用。
  - 效果：50 MB 合成 wire，后续查询从每次 37 ms 降到每次约 15 µs。
- **第 4 条（停止上限）：改对了，别家不受影响（另见新问题 2）。**
  - 什么时候设上限：只有带停止子树（也就是 Kimi）时，最后一步 KILL 之后才设 `stop_deadline = now + 5 秒`。
  - 到点之后：主循环每一轮先看是否到了上限，到了就记下残留 PID 再退出。上限过后，`Drop` 里的 waitpid 改成非阻塞。
  - 正常停止不会被截断：KILL 之后子树几毫秒内就清空，走的还是原来的退出条件。
  - 别家：`stop_deadline` 永远是 None，`Drop` 照旧阻塞等 waitpid，行为不变。
  - upgrade 交接：`stop_deadline` 进快照，新 pen 沿用同一个绝对时间；旧 pen 不认识这个字段，降级时会回到不限时（和上一轮第 8 条一样，可以不改）。
  - 测试：dev 的快照测试实打实等 5 秒，父进程已退出、未退出两种情况都核对了 pen.log、`remaining_pids` 和退出码。测试自己起的子进程由守护线程清理，全套跑完没有残留。

### 新问题

1. **建议改：每轮第一次从头读 wire，比原来慢 3.5 倍。** 位置：`crates/corral/src/agents/kimi.rs` 的 `wire_events` 里的行筛选。
   - 现象：筛选改成了 `line.windows(kind.len()).any(|bytes| bytes == kind.as_bytes())`，对不含关键字的长行，要按 7 种类型各做一遍逐字节窗口比较。同一个临时测试里新旧函数对比，50 MB 合成 wire 从头读一遍：旧版 37 ms，新版 129 ms。
   - 范围：只在每轮第一次查询（或 cursor 失效后）发生，之后的查询是微秒级，所以总的来说仍是大改进。这条退步是我上一轮“换成按字节查找”的建议没写清楚造成的。
   - 改法：每行只算一次 `let raw = String::from_utf8_lossy(&line);`（行是合法 UTF-8 时不复制），再用 `raw.contains(kind)`。注意不要把 `from_utf8_lossy` 放进闭包里每种类型算一遍：我试过，那样还要 105 ms。
2. **建议改：残留进程只记在内部文件里，`corral stop` 看不出来。** 位置：`pen.rs` 写 `exit.json` 的地方，以及 `cli.rs` 的 `stop`。
   - 现象：到了上限还有残留时，PID 只写进 pen.log 和 `exit.json.remaining_pids`。`corral stop` 照样返回 `ok:true`，调用方（paddock、派活）看不出没停干净。而按规矩前端不读 `~/.corral` 的内部目录，CONTRACT 里写的 `exit.json` 字段前端用不上。在这之前，同样情况下 `stop` 会报 timeout，至少调用方知道出了问题。
   - 改法：有残留时，`corral stop` 的输出带上 `remaining_pids`（兼容新增）。CONTRACT 改成写在 `stop` 输出里，并写明对 paddock 的影响。
3. **可以不改：停止上限的单测要实等约 10 秒。** 测试要求耗时在 5 到 7 秒之间，机器很忙时有可能偶发失败。这次全套并行跑是通过的。
