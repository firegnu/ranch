## 要做的

1. **看**：fence 能报出每个查资料服务器的名字、说明、地址、来源（内置还是本机加的）、有没有配 key（只报有没有，不报内容），以及每个档案现在实际选用的是哪一家（本机补充里写了以本机补充为准，否则是档案默认）。
2. **选用**：一条命令把选用设成某一家（一次只选一家）；也能恢复成档案默认。只改 `~/.fence/local.toml` 顶层的 `mcp` 这一项，文件里其他内容、顺序和注释原样保留；文件不存在就新建。选一个不存在或读不了的服务器时拒绝，什么都不改。
3. **添加、删除**：添加就是写 `~/.fence/mcp/<名字>.toml`（字段和 R30 一样：说明、地址、key 的请求头名和前缀），写之前用 R30 同一套检查，不合格拒绝、不写。不能用内置服务器的名字添加。删除只删本机加的；内置的删不掉；正被选用的那家不能删，要先换。删除时把它的 key 一起清掉。
4. **key**：写入一条命令、清除一条命令。key 只从标准输入读，不经命令参数、不回显；写入沿用 R30 对 key 的检查（含 `$` 等不合格的拒绝，不写）；写成只有本人能读的文件，写到一半失败不能留下半个文件或坏文件。原来的 key 是符号链接时不跟着链接写到别处，拒绝并说明。fence 的任何输出（包括这组新命令、`check`、`denials`、运行记录、报错）都不含 key 内容。
5. **测试连不连得上**：一条命令对一个服务器（没选用的也能测）在墙外连一次：做 MCP 的握手、取工具列表，配了 key 就带上。不真搜，不消耗搜索额度。成功报告工具名和用时；失败分清原因：连不上或超时、key 不对（服务器拒绝认证）、要网页登录授权（fence 不支持）、对方不是 MCP 或回的看不懂、没有工具。有超时，不会一直挂着。不记录测试结果。对方回的报错正文要处理，不能把 key 原样带进输出。
6. 先改 DESIGN §8 写清这组命令的用意和边界，在 CONTRACT 里写清命令、参数、JSON 字段、退出码（paddock 照这个做界面），再实现。README 的「怎么换成别的搜索服务商」补上用命令做的步骤。写清对 paddock 的影响。
7. 可以加依赖：保留格式改 TOML 的库、HTTP 客户端，用成熟、活跃维护的；工作区里已有的优先。
