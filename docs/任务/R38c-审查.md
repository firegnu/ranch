### 逐条核对

- **建议改 1（`PONY_HOME`）**：做对了。`src/main.rs` 的 `home()` 先用 `components().collect()` 去掉末尾的 `/` 和 `.`，再 `std::path::absolute`；空的 `PONY_HOME` 退回 `HOME`；`HOME` 没设或为空报 `invalid_data`。测试加了 `<链接>/`、`<链接>/.`、空 `PONY_HOME`、没设 `HOME`，还查了不会落到当前目录。我另试了 `<链接>//` 也被拒绝，`./h`、`h/./` 这类相对写法照常可用。`..` 结尾的写法最后一段不是链接，打开的是一个真目录，和直接把那个目录设成 `PONY_HOME` 一样，不算绕过。
- **建议改 2（未知键）**：做对了。`src/core/config.rs` 改用 `toml::de::DeTable::parse` 拿到键的位置：顶层、适配器段（核心的 `owner`、`channels` 加上适配器的 `config_keys()`）、频道项（`id`、`repo`）里的未知键都报错。裸键写出键名和行号，引号键只报行号；解析只做一次，`Table` 由同一份结果反序列化出来。我另试了 `[[slack.channels]]` 数组表、`slack.bogus` 点号键、`[slack.extra]` 子表、`[ slack ]` 带空格的表头、频道项里嵌套的内联表，都能报出 `slack.…` 的位置；Unicode 引号键、空引号键只报行号，没有 panic；`["slack"]` 这种引号表头照常接受。

### 可以不改

1. **长得像 token 的裸键会被写进 `config_message`**（`src/core/config.rs`，`reject_unknown_keys`）：实测 `xoxb-123-456-abc = 1` 报 `unknown key xoxb-123-456-abc`。这是我在建议改 2 里给的改法（裸键写出键名）留下的余地：Slack token 的字符都在裸键允许的范围里。要有人把 token 当成键名、后面还跟着 `= 值` 才会出现；只写一个 token 或者 `token =` 后面没有值，都是语法错误，只报行号。以后想更保险，可以对 `CHATS` 里各家声明的 token 前缀（`xoxb-`、`xapp-` 等）不写键名，或者干脆只写行号。
2. **`HOME` 没设时 `pony status` 退出 1、`ok:false`**（`src/main.rs`）：主控定的是「`HOME` 没设报错」，做的人照办了。只是 CONTRACT 写的是 `status` 只有参数错才不是 `ok:true`（退出 2），这个情况 CONTRACT 里没写。paddock 和 launchd 起的进程都有 `HOME`，实际碰不到；要和 CONTRACT 严格一致，可以给 CONTRACT 补一句，或者改成 `ok:true`、`config: invalid`。
3. **刚启动还没校验完凭证的那几毫秒，在跑的 `connecting` 的 `since` 是 `null`**（`src/core/status.rs:166-170`）：CONTRACT 括号里列的「不知道」只有「没跑过、或上次没留下退出记录」两种，这是第三种。时间很短，`null` 也合「不知道时为 `null`」的意思；想更准，可以用这次运行的 `started`。
