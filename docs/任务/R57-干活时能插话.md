## 已知的（主控 11-09 查的）

- `corral send` 只在 `idle` 时送：`working`、`blocked`、`starting` 一律退回 7 `not_idle`（`crates/corral/src/cli.rs` 的 `send_once`）；`--force` 只跳过「30 秒内有人操作」，跳不过这道。送达靠 agent 的输入事件确认（`confirmation`，文字摘要一致或包含在 `last_prompt` 里），15 秒内没确认报 3 `not_delivered`，不补发按键。
- 来历：老 Python corral 试验时（`../corral/docs/SPIKE.md`「问题 A」，09-15）往开着 `/model` 菜单的 Claude Code 送话，回车落在菜单上改掉了用户的默认模型。改法是「只在 idle 时送、不补发回车」，把 `working` 和 `blocked`、`starting` 一起挡了，挡 `working` 没有单独的理由。

1. **各家实测**：Claude Code、Codex、pi、omp、Kimi、amp、canter 各开一个测试 agent，让它做一件要跑一会儿的事（例如跑一条十几秒的命令），趁 `working` 打字回车插一句话。agy 只看文档、不实测。每家记：
