## 审查意见

改完再合并：必须改 2 条，建议改 0 条。审查对象为 `bff5fbd`，以下问题均用隔离 HOME、CORRAL_HOME 和 `/bin/cat` 合成程序复现；没有启动真实 agent。

1. **必须改：pi 的扩展对话框关闭会抹掉中断原因，重新把旧回复当成已完成。**
   - 位置：`crates/corral/src/events/raw.rs:99–104` 的 `ui_prompt_end` → `Stop`，与本次 `crates/corral/src/events.rs:79–86` 清除中断标记的逻辑交互。
   - 问题：完成一轮并保存 `previous reply` 后，依次输入 pi 的 `before_agent_start`、`agent_settled {aborted:true}`、`ui_prompt_start`、`ui_prompt_end`（最后一条顶层 `idle:true`）。最后两条只是打开、关闭扩展对话框，没有开始或完成新的模型轮次，但关闭时生成的 `Stop` 清掉 `interrupted`，且没有新回复可替换旧回复。实测最后为 `state:idle, interrupted:false`，`wait.result:idle`，`reply` 退出码 0、`text:previous reply`，同一条提醒以 `wait_result.result:idle` 提前送出。R22 要消除的误判因此重新出现。
   - 可达性：核对了本机 pi 1.3.0 的实现。`agent-session.js` 的 `prompt()` 先处理扩展 slash 命令，命令处理成功就直接返回，不触发 `before_agent_start`；`extensions/runner.js` 的 `withUIPrompt()` 会为扩展的 select/confirm/input/editor/custom 对话框发开始、结束事件。因此人在打断后打开再关闭一个扩展对话框，就可出现这组事件，无需丢钩子或伪造异常事件。
   - 改法：把 UI 对话框关闭后的空闲恢复与真实轮次结束区分，保留已有的中断标记和回复保护；真正的新输入或正常结束仍按现有约定清除标记。补上「中断 → 扩展对话框开/关 → 仍不能返回旧回复或按 idle 送提醒」回归测试。

2. **必须改：旧中断标记会压住后续 blocked 提醒，与保留原有 blocked 规则的约定不一致。**
   - 位置：`crates/corral/src/after.rs:172–178`；对照 `cli.rs:351–359`、`docs/CONTRACT.md` R22 的「原有……blocked……规则不变」，以及 guide 中「卡在对话框时送提醒」。
   - 问题：`interrupted` 与 `paused` 一起放在所有状态判断之前，不只跳过被打断的 idle。用上条相同的 pi 中断序列，随后只发 `ui_prompt_start`，保持对话框打开：`status` 为 `blocked/interrupted:true`，`wait.result` 正常返回 `blocked`，但 `--after` 一直等，直到截止时间才返回 `wait_result.result:timeout`。这会漏掉原本用于提醒主控请人处理对话框的通知；本次改动前这条路径按 blocked 触发。
   - 改法：保持暂停的优先级，将中断抑制限定为「state 为 idle 且 interrupted 为 true」，让 blocked 仍走原有稳定等待及提醒逻辑；保留 restarted 优先、原截止时间和接收端的人类输入保护。补上「中断后出现 blocked，wait 与 after 都按 blocked 处理」回归测试。它与第 1 条分别发生在对话框打开、关闭阶段，只修其中一条不够。
