### 1. 必须改：Codex 同名 MCP 配置会保留旧认证字段并改向 Exa

- 位置：`crates/fence/data/agents/codex.toml:7`。
- 问题：`-c 'mcp_servers.fence_exa={url="https://mcp.exa.ai/mcp"}'` 没有整份替换已有 server。Codex 把它构造成最高优先级的配置层，再递归合并 TOML 表；没有出现在这次参数中的 `http_headers`、`env_http_headers`、`bearer_token_env_var` 等字段仍会保留。用户若原来通过同名条目连接自己的认证代理，新的 URL 会配上原有凭证。
- 具体触发条件：例如已有以下配置（认证值为说明用假值）：

  ```toml
  [mcp_servers.fence_exa]
  url = "https://research.example.invalid/mcp"
  http_headers = { Authorization = "Bearer review-placeholder" }
  ```

  套墙后有效配置的 URL 变成 Exa，`Authorization` 仍是上述值。HTTP 客户端会将保留下来的 header 放入发往该 URL 的 MCP 请求。无需修改磁盘上的配置文件，也无需模型主动读取凭证，就能发生这条泄露路径；允许访问 `mcp.exa.ai` 的墙不会阻止它。不存在同名条目的默认安装不触发此问题。
- 依据：Codex 0.163.0 的 [CLI 配置层构建](https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/config/src/loader/mod.rs#L253-L268)、[有效配置合并](https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/config/src/state.rs#L530-L538)、[表项递归合并](https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/config/src/merge.rs#L97-L155)，以及 [HTTP 请求组装](https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/rmcp-client/src/http_client_adapter.rs#L143-L244)。官方 [MCP 配置说明](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) 也明确这些认证字段会成为请求头。
- 改法：接入时避免与既有 server 表合并，例如使用确认无冲突的会话专用 server 名，冲突时拒绝启动；或者采用客户端支持的隔离接入方式。保留用户其他 MCP 配置，不修改全局文件。仅加 `http_headers={}` 不能清除旧表中的键。修复时用假认证值覆盖上述同名场景，验证原 server 不被改向、Exa 请求不带旧认证；不需要接真实 Exa 或模型服务。

### 4. 可以不改：临时资源的写入时序未形成墙外执行或跨实例写入入口

- 位置：`crates/fence/src/runs.rs:154–178`、`:188–212`，`resources/runner.mjs`。
