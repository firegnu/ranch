## 3. 要做的：第 1 部分，改 corral-dispatch 技能正文

改 `crates/dispatch/resources/corral-dispatch/SKILL.md`。

### 3a. 派活的先后：先写正文，再问路由

1. 先写任务书正文：做成什么、范围、要做的、不要做、验收（照抄用户原话）。这些和交给谁无关。
2. 从正文提炼三五句摘要（做什么、改哪里、做错了影响什么；不带验收和验证方式），问路由。
3. 照 3b 的分工表定交给谁、模型、强度。打算交给 pi、omp 的，拿正文对一遍 3d 的「说得清」检查，过不了就按第 8 条交。
4. 补上依赖结果的几行：开头的「交给谁、几档」、路由那一行、「怎么算做完」里的验证预算（影响面）。交给 pi、omp 的，看正文要不要写得更具体。
5. 派出。

### 3b. 分工表：从上往下看，第一条命中的算数

| # | 条件 | 交给 | 模型 / 强度 |
|---|---|---|---|
| 1 | 任务文件写了 `执行：主控`，或者用户让主控自己做 | 主控自己做，不派 | — |
| 2 | 用户点名 | 照用户说的 | 照用户说的；没说的部分按下面各条 |
| 3 | 项目 AGENTS.md 有规定 | 照规定 | 照规定 |
| 4 | 本轮要改代码，并且碰要害（路由交叉审查判「要」，或者主控判断碰了数据模型、并发和事务、安全和隐私、核心规则） | 设计和界面给 Claude Code，其余给 Codex | opus[1m] / high，或 astra / high |
| 5 | 项目代码之外的杂活（本机清理、一次性脚本、核对数据、跑命令汇报） | pi、omp | 各自默认 |
| 6 | 要出方案或做取舍：设计、新界面、新交互、跨模块；涉及界面或产品取舍的调研 | Claude Code | opus[1m] / high |
| 7 | 界面活，并且过了 3d 的「说得清」检查 | pi、omp | 各自默认 |
| 8 | 其余界面活（单个组件，可以有小的行为改动，不新做交互） | Claude Code | 见第 7 节第 2 问（试用 sonnet / high，或者 opus / medium） |
| 9 | 其余：照方案实现、修 bug、补测试、机械改动、查事实或定位问题的调研 | Codex | astra，强度见 3c |

- 用户点名（第 2 条）和项目规定（第 3 条）只决定交给谁。碰要害的活照样要交叉审查，验证预算照样按影响面定。
- pi、omp 两家同类，任选，一家手上有活就开另一家。amp、agy 照旧：只在点名时派。
- 「拿不准哪家给 Codex，因为 Claude Code 有周限额」这条删掉：第 9 条已经覆盖了，而用户说过不是为了省额度。

### 3c. 分档表：强度

| 强度 | 用在哪 |
|---|---|
| medium（中档） | 第 9 条的默认：一般的 bug；在已经理解的代码里加小功能；照方案实现；查事实的调研。路由的 `tier.level` 是轻或常规时用 |
| high | 第 4、6 条固定用 high。第 9 条在路由的 `tier.level` 是重，或者主控判断是跨好几个文件的改动、原因还不知道的 bug、有取舍的设计时，也用 high |
| xhigh | 只给交叉审查（Codex astra / xhigh） |

- 用 `tier.level`（三档里概率最大的那档，总有值），不再用 `tier.verdict`（置信度不到 0.8 就是 null）。这样档位就不会出现「拿不准」，路由 JSON 也不用改。
- 不用 low：paddock 看板不认这一档。
- 「很费 token 要先问用户」（fable、opus 开 max、Codex 开 ultra）不变。

### 3d. 「说得清」检查（第 7 条用）

下面四条全部满足，才交给 pi、omp：

1. 只改显示：颜色、字号、间距、对齐、图标、文案；不改数据、状态和输入处理。
2. 有要照着做的样子：用户给了截图或具体的值，或者项目里有现成的画法可以照。
3. 改动点能一条条列出来，不新建模块。
4. 没有待定的设计问题。

### 3e. 影响面和交叉审查

- 影响面三档（看得见、改行为、碰要害）和各自的验证预算不变。
- 新加一条：类型是调研或设计、本轮不改代码的活，影响面一律算「看得见」，不交叉审查，不管路由说什么。以往有两次推翻就是这种情况：P5-23r、P5-90a 只读调研，路由因为提到安全判成碰要害。这条只改技能正文，不改路由代码。
- 交叉审查的其余规矩不变：只给碰要害的活，交给 Codex，用 astra / xhigh。技能第 6 节「用『重』档」改成写明 astra / xhigh。

### 3f. 记录结果，做不好怎么办

- 主控审查末尾加一行，三选一：`结果：一次过`、`结果：返工 N 次`、`结果：返工两次仍不达标，已停下问用户`。
- 照现行规则交回原来的 agent 返工。返工两次还没达到「怎么算做完」，就停下来问用户：换一家、升一档，还是放弃。暂不做自动升层。
