## 现在怎样

- 对方在干活时，pony 把话排队，`→ X（正在干活，这句排在第 n 个，这一轮结束就送）`，这一轮结束再送（用户定的第 5 条）。
- pony 有十几处靠 `turn_started` 判断这一轮结束没有、回复贴哪个线程、按钮还算不算数。插话会让 corral 刷新 `turn_started`（R57b 没改这个含义）。所以现在只要有人对 pony 正在跟踪的 agent 插话（主控、终端、以后的 paddock），pony 就可能把这一轮当成新的一轮：原线程等不到回复、回复贴错或贴两遍、「打断」按钮报「已经开了新的一轮」。

## 用户定的（11-09，照主控的建议）

1. **哪些话插、哪些照旧排队**：只有「线程里新来的话、对方在干活、`capabilities.steer` 为 1、这家支持」才插；离线补收的话、提问框回答、已经排着的话照旧排队。
2. **插话以后回复贴哪**：这一轮结束的回复贴回开这一轮的那个线程；插话的线程和它不同时，插话线程里只回一句「已插进 X 正在做的这一轮，做完的回复贴在 <原线程链接>」。
3. **从别的线程插话算不算换了一轮**：不算，原线程的等回复、「打断」按钮都照旧有效。不是 pony 开的一轮（例如主控自己在干活）被 Slack 插话时，这一轮的回复贴回插话的线程，不再另发顶层提醒。
4. **插不进去时**：`unsupported_steer`、`unsupported`、`not_idle`、`state_changed` 照旧排队，线程里说一句原因；`draft_not_submitted` 不排队（字已经在对方输入框里，再送会重复），线程里说「写进去了但没提交，请回电脑看一下」。
