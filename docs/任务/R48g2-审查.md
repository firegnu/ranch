### 1. 必须改｜子 agent 的框不计数，「只有一个框」不成立，`1` 和后台答案的数字会落到子 agent 的批准框上

- 位置：corral `crates/corral/src/agents/kimi.rs` 331–417、502–518 行（只读主 wire）；pony `crates/pony/src/corral.rs:63` `kimi_dialog`、`engine/approvals.rs:284` `kimi_prompt`、`engine/kimi.rs:315` 后台按键。

### 2. 必须改｜上一个 Kimi 进程留下的框会变成一直开着的「幽灵框」：pony 会在空闲的 Kimi 上按两次 Esc，或往输入框里打字加回车；corral 一直报 blocked，`send` 一直 not_idle

### 新问题

#### 1. 建议改｜子 wire 里有一行解析不了，这个会话以后就一直读不到计数

后果：Kimi 在 Slack 上的允许、后台答案、拒绝和「停」全部失效。

- 位置：corral `crates/corral/src/agents/kimi.rs:282–290`（`child_dialog_count`）。
- 问题：子 wire 逐行读，最后一行没有换行也照样解析。只要有一行含 `interaction.` 又解析失败，整个函数就返回 None，`interaction` 变成 null。时间过滤在解析之后，所以上一个进程留下的坏行也算在内。主 wire 的读法不一样：遇到没写完的末行就停，坏行跳过。
- 什么时候会出现：
  - Kimi 被停的时候正好写到一半，留下半行。Kimi 自己有截断修复（`wire/repair.ts`），说明这种半行确实会有；恢复会话时它不一定会去修子 wire。
  - 读的时候子 agent 正在写，只读到半行。
  - 含 `interaction.` 的行不只是交互记录。子 agent 读到含这个词的代码或输出，工具结果里也会有，比如在这个仓库里读 `kimi.rs`。
- 会怎样：方向是保守的，不会按错键。但是：
  - 坏行一直在，这个会话以后每个实例都读不到计数：允许和拒绝按钮都不给，「停」被拒，提示「无法核对 Kimi 的框」。
  - 排着的后台答案只要碰到一次 null 就被撤掉，给的理由是「题目已处理、已换或有别的框」，不准确。
- 复现：临时测试 `review2_bad_old_child_line_nulls_interaction_forever`。子 wire 里留一行上一个进程写了一半的 tool.result（含 `interaction.request` 字样，没有换行），新实例的主 wire 有一个批准。status 为 `state:"blocked"`、`interaction:null`；批准解决后仍是 null。
- 改法：
  - 和主 wire 一样，没有换行的末行这次先不读，下次再读。
  - 完整但解析不了的行，只在无法判断它属于本实例时才算读不到，或者直接跳过。
  - 撤后台答案时，如果原因是 interaction 为 null，理由写成「无法核对」。

#### 2. 建议改｜批准提醒的代码块围栏固定是三个反引号，命令里有单独一行三个反引号就会提前结束代码块

- 位置：pony `crates/pony/src/core/engine.rs:2395`。同一个函数里读屏的分支（2432 行）已经会按内容加长围栏。
- 问题：用 heredoc 写 markdown 的命令很常见，例如 `cat > notes.md <<'EOF'` 后面跟一段用三个反引号包起来的内容。
  - 命令里第一行单独的三个反引号就会关掉 pony 的代码块。之后的命令按 markdown 渲染，`**`、`_`、反引号都被吃掉，看到的和要批准的不一样。
  - pony 结尾的三个反引号可能又开出一个代码块，把后面「这里只提供…要拒绝：点『拒绝』或回『停』」的说明吞进去。命令里的代码块开头写成「三个反引号加 bash」、结尾是单独的三个反引号时，就会这样。
  - 这种命令完整、不危险，所以仍然给「允许这一次」。确认框里是原文，但只显示前 200 字。
- 复现：临时测试 `review2_kimi_command_fence_closed_by_command_content`。命令共五行：`cat > notes.md <<'EOF'`、三个反引号、`` **说明** _a_ `b` ``、三个反引号、`EOF`。提醒正文里，pony 的代码块在命令第一行之后就结束了，按钮里有「允许这一次」。
- 改法：围栏长度取命令里行首最长的那串反引号再加一个，或者照读屏分支改用足够长的 `~` 围栏。补一个命令里含三个反引号的测试。

#### 3. 可以不改｜每次 status 都把所有子 wire 从头读一遍

#### 4. 可以不改｜子框和主框同时开着，子框先处理掉后，主框不会重新提醒
