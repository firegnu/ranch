## 要做的

1. **适配器接口加读屏规则**：`Adapter` 新增一个方法，返回这家的读屏规则，默认为空。现有四家和 amp 不写，行为不变。
   - 一条规则：看哪块（屏幕最下面 n 行非空的行，或整屏）、怎么匹配（都要有哪些字、不能有哪些字）。
   - 这一件里规则只能判出 `blocked`（agy 缺的就是「等批准／等回答」）。要不要判 working／idle，到 agy 那件按真实需要再说。
2. **pen 里常驻一份屏幕**（新依赖 `vt100 0.16`，MIT）：
   - 只有声明了读屏规则的那家，pen 才建屏幕、喂输出。别家的 pen 不建，不多占内存和 CPU。
   - 输出来一段喂一段；终端大小变了跟着改。
   - pen 的内部状态回复里给出当前屏幕的文字（只在有屏幕时给）。这是 pen 和命令行之间的内部协议，属于兼容新增：旧版命令行不看这一项，新版命令行碰到旧 pen 没有这一项就不读屏。
   - `corral upgrade` 的快照里不带屏幕。新 pen 起来后用输出环最后一段重建屏幕，快照格式不变。
3. **命令行合并状态**：放在算状态的那一处（R6 标题规则所在的地方，`status`、`wait`、`send` 的空闲检查、提醒都经过它）：
   - 钩子报的是 working 或 idle，而屏幕命中这家的规则时，报 `blocked`。
   - 钩子说了算的状态（`blocked`、`starting`、`unknown` 等）不改。
   - 每次读状态时按当前屏幕现算，不锁存：屏幕上的提示框没了，`blocked` 就回到钩子的状态。
4. **文档**：DESIGN §7 写读屏这一档（放哪、规则怎么写、钩子优先、不锁存、只对声明的那家生效）。CONTRACT 不用改（公开输出不变）。
