## 用户已定的（10-20、10-21 在 paddock 主控那里谈定，原文见 P5-147「已定的」）

- **插件式**：照 ranch 接不同 agent 的做法，每家聊天软件一个适配器（连接方式、凭证、@ 的写法、有没有线程、消息长度和格式），登记在一张表里；共用核心不写任何一家的名字，管 @ 谁对应哪个 agent、权限、聊天线程和 agent 对话的对应、长回复裁剪、提醒。
- **和 agent 只走 corral 公开命令**：send、wait、reply、status、ls。
- **分两期**：第一期：@ 已经在跑的 agent 说话（送过去、等这一轮结束、回复贴回同一线程，线程里接着回就是接着聊）；Needs you 和主控新回复在对应频道提醒，在提醒的线程里回复直接送给这个 agent；看状态（哪些在干活、哪些在等）。第二期：在聊天里开、停 agent，以后另开。
- **一个频道对应一个仓库**：
  - 频道在配置里绑一个仓库；频道里 `@机器人 说话` 默认送给这个仓库的主控（`<仓库>/main`）。仓库就是 agent 全名斜杠前那段。
  - 第一个词是同仓库某个 agent 的短名，就送给它；跨仓库写全名（`ranch/main`），只能送给绑了频道的仓库。
  - 线程里回复不用再 @，送给线程开头那个 agent。
  - 机器人先回一行 `→ <agent 全名>`；写了带斜杠的全名但没有这个 agent 时报错，不转给主控。
- **没绑频道的仓库一个字都不发到 Slack**：没有总频道；提醒、回复、看状态都只涉及绑了频道的仓库；跨仓库写全名指向没绑频道的仓库时，只回「这个仓库没接入 Slack」，不送、不转。默认不接入，要接入就给它绑一个频道。绑了频道的仓库，回复原样整段发出去，第一期不做内容过滤。
- **先接 Slack**（线程完整；Socket Mode 由机器人往外连，本机不需要公网地址）。
- **第一期只有用户自己能用**：只接受配置里列出的那个用户 ID，同频道里别人的消息一律不理。
- **第一期只在这台 Mac 上开**：只管本机 agent；别的机器（如 5090）装了 ranch 也默认关着（两台机器连同一个 Slack 机器人，Slack 会把消息随机交给其中一条连接）。
- **凭证只放本机**：不进任何仓库，也不出现在给 paddock 的输出里。
- **给 paddock 的**：一条只读命令，输出 JSON，至少有：在不在跑、连没连上（连不上时的原因）、绑了哪些频道各对应哪个仓库。写进 `docs/CONTRACT.md`。paddock 的 P5-147 照它做 Settings 显示（验收第 7 条）。
